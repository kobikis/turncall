# ADR-0029: pipecat 1.14 — fixes for nothing, two deprecations cleared

**Status:** Accepted
**Date:** 2026-10-27
**Supersedes:** nothing. Follows ADR-0028 (each pipecat minor on purpose).

## Context

pipecat 1.14.0 came out on 2026-10-23. ADR-0028 caps pipecat at the next minor,
so nothing picked it up until this. Unlike 1.13 it rewrites nothing TurnCall
reaches into: the full suite passed on it unchanged (the only failures were
load flakes in SMS and webhook tests that pass on both versions when rerun).
The lock moves `pipecat-ai` alone; `aiohttp` was already past 1.14's 3.14.4
security floor.

## Decision

Take the bump whole, as ADR-0019 and ADR-0028 did, with no behaviour change
beyond what is listed below. New features become follow-up issues.

**1. No deprecation of ours is left.** 1.14 deprecated two things TurnCall used:

- `text_filters` (and `BaseTextFilter`), which `StageDirectionFilter` was. It
  is now `stage_direction_transform`, a TTS text transform registered **first**:
  `strip_markdown` after it would drop the asterisks a starred narration is
  recognised by. It was a filter only because an emptied transform used to be
  sent as a request; 1.14 leaves it unspoken. Same text reaches the voice.
- `pipecat.adapters.schemas.*`, now `pipecat.adapters.llm.schemas.*`.

Tests that still used names 1.13 deprecated (`AggregationType`,
`aggregated_by`) use `TextType` / `text_type`. A cascade call's build is now
pinned like the eval path (`test_call_build_no_pipecat_deprecations.py`, in a
child process, since a deprecated module warns once on first import), so the
next minor's deprecations are a red build. pipecat's own internal one
(`AudioContextTTSService`, subclassed inside `tts_service.py`) is excluded by
name.

**2. Our pipecat workarounds stay.** The three `test_pipecat_still_needs_it`
pins — `realtime_appends.py` (#388, #390), `webrtc_offer.py` (#398),
`SpeechBeforeAmbience` (#265) — still pass: 1.14 fixed none of those bugs.

## Fixes TurnCall gets for nothing

- **OpenAI Realtime** stopped handling server events for the rest of a session
  after a `response.done` without `usage`/`status_details`, or an event type it
  had no model for. Our `openai` S2S provider is that service.
- **WebSocket sends are bounded at 5 s.** A provider that stopped reading held
  its processor, and every one after it, until TCP gave up — minutes of dead
  air with no error. Now the send fails and the service's reconnect takes over.
- **Deepgram Flux** reconnects in the background, retries a connection that
  never says `Connected` (gives up after three), and a connection that drops
  mid-turn ends the turn with what it had, instead of losing it.
- **Deepgram's refusal reason** (e.g. an out-of-range setting) is in the error,
  so in `error.raised`, rather than a bare `HTTP 400`.
- **Text-mode evals of an agent with a failover group.** The eval client sends
  each text turn as `send-text` with `run_immediately`, which flushes the
  pipeline first, and the flush never drained a `ServiceSwitcher` — every
  failover group is one — so each turn waited for the pipeline to go quiet.
  Measured: one turn took ~6 s on 1.13, ~1 s on 1.14
  (`test_a_text_turn_reaches_an_agent_with_a_failover_group`, which fails on
  1.13).
- **ElevenLabs word timestamps** no longer run early after punctuation that
  arrives on its own, so the spoken-text frames line up with the audio.
- **Cartesia** keeps a regional language (`es-MX`) instead of reducing it to
  its base.
- **`redact_secrets`** (so every `ErrorFrame`, whose text reaches `error.raised`)
  no longer leaves a credential unmasked when it follows another `name: value`
  pair, nor recurses to death on long `a:a:a…` text.

## Behaviour that changes with the bump, accepted

- `strip_markdown` speaks a Markdown link's label, not its URL.
- On a TTS without word timestamps (OpenAI, xAI's HTTP service), the
  assistant context keeps the LLM's text as written, stage directions
  included; it used to keep the filtered text. The caller still never hears
  them and the transcript tap still strips them. #409 strips them once, at the
  LLM, so every voice keeps the same history.
- A WebSocket send stuck 5 s drops the connection and reconnects.
- While Flux reconnects, the caller's audio is not transcribed; a Flux that
  stays down is the STT stall failover's (`orchestrator/failover.py`).

## Not adopted, and why

- **New providers** (Perplexity Agent, Smallest, Zoom Scribe, NVIDIA Omni,
  Speechmatics at 8 kHz): none until someone asks. Live web answers are the one
  capability TurnCall lacks, and they belong in a tool the agent's LLM calls
  when it needs the web, not in the LLM every turn waits on — #410.
- **OpenAI Responses over WebSocket** as a cascade LLM: only if it beats Chat
  Completions' TTFB by ≥15% median by turn 5 with no worse p95 — #411.
- **Gemini 3.6 Flash's retirement** is Vertex AI's (2026-11-19). The Gemini API,
  which the `google` provider uses, still serves it without a deprecation, so
  the house model stays.
- Twilio API-key auth on pipecat's serializer: TurnCall's serializer is its own.
