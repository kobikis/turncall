# ADR-0033: pipecat 1.16 — two minors at once, one missing attribute

**Status:** Accepted
**Date:** 2026-11-13
**Supersedes:** nothing. Follows ADR-0028 (each pipecat minor on purpose) and
ADR-0029 (pipecat 1.14).

## Context

pipecat 1.15.0 came out on 2026-10-28 and 1.16.0 on 2026-11-11. ADR-0028 caps
pipecat at the next minor, so neither reached an install. Together they are
about 2,100 changelog lines: a rewrite of how user turn strategies combine
(1.15), a new resampler package replacing soxr and resampy (1.16),
expressive conversation (alpha, both), and a long list of fixes.

On 1.16 the full suite had 3 failures in 3,957 tests:

- `SharedSmartTurnAnalyzer` skips `LocalSmartTurnAnalyzerV3.__init__` and
  copies what it sets. 1.16 sets one more thing, `_resampler`, which the
  analyzer creates on first use to bring a call's audio to the model's rate.
  Without it the analyzer raises on the first turn of every call it serves.
  `test_smart_turn_shared_model.py`, which compares the two constructors, is
  what caught it.
- Two Gemini Live greeting tests: 1.16 re-opens the session on the first
  context when the composed system instruction differs from the one sent at
  connect (pipecat #6289), and the tests' fake session cannot be re-opened.

## Decision

Bump straight from 1.14 to 1.16 in one PR (`>=1.16.0,<1.17.0`), whole, with no
behaviour change beyond what pipecat forces, as ADR-0019, 0028 and 0029 did.
New features are follow-up issues.

**1. What the bump changes in TurnCall.**

- `SharedSmartTurnAnalyzer` sets `_resampler = None`, as pipecat does. It
  belongs to the call, never to the shared model: a stream resampler carries
  audio between frames.
- `text_matches` (1.15, regular expressions an event's text must match) counts
  as an assertion in `evals/scenario._ASSERTING_FIELDS`. Without it a scenario
  asserting only by regex would be told it cannot fail (#95).
- The xAI STT (#394) sends `keyterm`, `filler_words`, `vad_threshold`,
  `smart_turn` and `smart_turn_timeout` as pipecat settings, which 1.16 added.
  Only `format` is still put on the URL by hand. `_send_finalize` stays: 1.16
  still sends no `finalize` when VAD hears the caller stop.
- The Gemini greeting tests leave the fake session as connect would and stub
  the re-open, and assert that the opening context does not cause one.
- The live Gemini test expects google-genai 3 (1.16's `google` extra).
- `torchaudio` is no longer a dependency: 1.16's `local-smart-turn` extra
  stopped installing it, nothing of ours imports it, and it was declared only
  to take it from PyTorch's CPU index (#377). `torch` stays declared for that.

**2. Checked, no change needed.**

- **Turn strategies (1.15).** Several stop strategies in one list now all have
  to agree before a turn ends (`stop_mode` defaults to `ALL`). Every set
  TurnCall builds has one stop strategy (Smart Turn, VAD, Flux's external one),
  so nothing changes. A future second one must choose its mode.
- **The workarounds stay.** `realtime_appends.py` (#388, #390),
  `webrtc_offer.py` (#398) and `SpeechBeforeAmbience` (#265): their
  `test_pipecat_still_needs_it` pins still pass.
- **No pipecat deprecation is reached** by a call's build or the eval path.
- **soxr** left pipecat's core dependencies; ambience upload declares and uses
  it directly. **audioop** is no longer imported by pipecat; our two
  serializers still use it (below).
- **Tool results.** A result of `""`, `{}` or `False` now runs the LLM; only
  `None` completes a call silently. No handler of ours returns one (an empty
  knowledge search answers `{"results": "No relevant information found."}`).
- **Gemini Live's re-open on the first context** happens for an agent with
  tools on 1.14 too (TurnCall puts the tools on the context), and not at all
  without tools on either: no new latency. The existing double open is #459.
- **gpt-live-1 delegation.** The private surface `delegation_events` reads
  (ADR-0028) is unchanged, and the #262/#413 tests pass on 1.15's shorter
  acknowledgements.

## Behaviour that changes with the bump, accepted

- Deepgram Flux turns end as soon as the finalized transcript arrives after
  Flux's end of turn, up to 0.5 s sooner.
- A reply whose TTS produced no audio (provider error, stall) no longer leaves
  its text in the agent's context.
- gpt-live-1's acknowledgement of a delegation is shorter and no longer said
  twice, and "never mind" reaches the delegate more reliably.
- Gemini Live retries a session that fails to open, then marks the service
  unusable; a reply cut off by a dropped connection ends cleanly.
- Claude Haiku 5.5 gets `effort: low` by default (and `claude-fable-5-2` too),
  so it no longer speaks its reasoning before a tool call; about +0.1 s on a
  clear turn and +0.6 s on one where it decides what to do. pipecat's default,
  not ours to override.
- google-genai moves from 2 to 3 under the `google` provider and Gemini Live.

Fixes that come with it, among them: OpenAI Realtime going silent with
`gpt-transcribe`; HeyGen gaps in long replies and HeyGen/Tavus clipping each
utterance's end; switchers (every failover group) growing in memory over a
long call; provider sockets left open after a call cancelled during shutdown
(Deepgram Flux counts them against its session limit); `strip_markdown` inside
inline code and links with brackets; a sentence-splitter panic that
`except Exception` does not catch; currency, unit and year reading in text
normalization.

## Adopted later, in this order

1. **Score real calls with the eval judge.** `EvalRubric` judges a
   conversation the harness did not drive. It is how #420's drafts from
   failing calls are judged; noted there rather than filed apart.
2. **LLM turn-completion markers**, opt-in, only if replays of recorded calls
   show fewer cut-offs than Smart Turn with no worse latency — #454. Measured
   on 47 recorded calls (2026-11-13): 10–17% fewer cut-offs, but p95 latency
   rose from 1.88 s to 2.22 s (Grok) and 2.10 s to 2.18 s (Gemini), and spelled
   emails and numbers were still marked complete. Not adopted; #454 closed with
   the numbers.
3. **OpenAI Realtime transcription keywords** from `stt.keyterms`, and session
   truncation — #455.
4. **`content_filtered` on `error.raised`** (1.16's `CONTENT_FILTERED`, which
   does not fail over) — #456.

Also filed: the serializers off `audioop` onto `pipecat.audio.g711` and the
Sinc stream resampler, checked by ear on a real call since it changes audio
(#453); `gpt-4o-mini`'s retirement on 2027-01-14, which pipecat's changelog
surfaced and which stored agents would hit (#458).

## Not adopted, and why

- **Expressive conversation.** pipecat calls it alpha and expects its APIs to
  change; 1.16 already moved its modules. On hold — #457.
- **New providers** (Rime STT, HeyGen Voice, AssemblyAI TTS, Zoom AI Realtime,
  Google Interactions, Sarvam HTTP STT): none until someone asks (ADR-0029).
- **Speaker diarization, the jambonz serializer, context summarization**: no
  TurnCall flow needs them.
