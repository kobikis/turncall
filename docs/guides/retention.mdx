A retention policy says how long a project keeps each kind of call data. A janitor deletes what has expired. Unset, which is the default, everything is kept, as it was before retention existed.

## Set it

```bash
curl -X PUT https://api.example.com/v1/projects/$PROJECT_ID/retention \
  -H "Authorization: Bearer tc_..." \
  -H "Content-Type: application/json" \
  -d '{"recordings_days": 30, "transcripts_days": 90, "events_days": 365}'
```

This needs an admin key, and a project can only set its own. Each field is a whole number of days from 1 to 36500, counted from the call's end, or `null` to keep that kind for good. The `PUT` replaces all three, so a field you leave out goes back to being kept for good. The project read (`GET /v1/projects/{id}`) shows the setting under `retention`.

An agent can override any of the three for its calls, in its config:

```json
{"retention": {"recordings_days": 7}}
```

A field the agent leaves `null` takes the project's. The override is read from the agent's live version (the published one, or the newest if none is published) and applies to the calls of all its versions, so publishing a new retention covers the agent's earlier calls too. After a handoff, the agent the call ended with decides. An inline agent from call-init has no stored version, and its calls take the project's retention.

## What each kind covers

- **Recordings**: the call's audio in your object storage (local or S3), and `recording_url` on the call.
- **Transcripts**: what was said and what was made from it. The `transcript.final` lines, the `tool.result` events and the call's tool invocations (a tool's arguments and result come from the conversation), `context.injected` messages, and the post-call analysis, which includes the summary, `structured_data` and takeaways.
- **Events**: every other event on the call's event log: lifecycle and carrier events, `metrics.turn`, `provider.failover`, `error.raised`, `recording.ready` and the rest.

## What stays

The call record itself is never deleted: its id, numbers, direction, status, times, duration, agent, `metadata` and `recording_status`. Three fields on `GET /v1/calls/{id}` say what was deleted and when: `recording_expired_at`, `transcript_expired_at` and `events_expired_at`.

After a kind expires, its reads return nothing for it:

| Expired | Read |
|---------|------|
| Recording | `recording_url` is `null`, `GET /v1/calls/{id}/recording` is `404` |
| Transcript | `GET /v1/calls/{id}/transcript` has no entries and an `expired_at`; `analysis` is `null`, `GET /v1/calls/{id}/analysis` answers `status: "expired"`, and a re-run is a `409`; the call's tool invocations are gone |
| Events | `GET /v1/calls/{id}/events` returns what is left of the transcript kind, or nothing; `latency_summary` is `null` and `failovers` empty |

`ended_reason` is worked out from the events, so it is saved on the call before they are deleted, and the read keeps saying how the call ended.

## In `call.ended`

Every `call.ended` webhook states the retention that applies to the call, with the agent's override already applied:

```json
"retention": {"recordings_days": 30, "transcripts_days": 90, "events_days": 365}
```

`null` means kept for good. It is the policy when the call ended; a later change applies to stored calls too.

## When it runs

Each server runs the janitor once an hour, so data is deleted within the hour after it expires. Several servers can run it at once: each takes the calls it deletes, and the others skip them.

A change applies to calls already stored. Shortening a retention deletes what is now past it on the next run; lengthening it keeps what has not been deleted yet, but nothing already deleted comes back. A call with no recorded end (a server that died mid-call) is counted from its start.

A recording object that cannot be deleted (storage unreachable) is logged as `retention_recording_delete_failed`, and the call is tried again on the next run, so a call is never marked expired with its recording still in storage.

## What it does not touch

- **The audit log.** It has its own retention; call retention never deletes from it.
- **Text conversations** (SMS, WhatsApp, the Chat API) are not covered yet.
- **A carrier's own copy.** If your Twilio account records calls itself, the copy Twilio keeps is subject to Twilio's settings. TurnCall deletes its own copy.
- **Logs, traces and webhook deliveries** that already left the server. Redact them with [redaction](/guides/redaction).
