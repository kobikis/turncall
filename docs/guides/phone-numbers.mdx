Phone numbers connect your Twilio and Telnyx numbers to TurnCall agents. Each number can route to a specific agent or to a webhook for dynamic routing.

A number's `carrier` — the telephony company it belongs to — is `twilio`, the
default, or `telnyx` (see [Telnyx numbers](#telnyx-numbers)), and is fixed once
bound: a `PUT` naming a different carrier is a
`422`. `provider` is accepted for it as a deprecated alias, and reads still
carry `provider` beside `carrier`; prefer `carrier`, since "provider" means an
STT, LLM or TTS backend everywhere else in the API.

## Bind a Phone Number

### Static routing (to an agent)

```bash
curl -X POST http://localhost:8090/v1/phone-numbers \
  -H "Authorization: Bearer tc_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "external_number_sid": "PNxxxxxxxx",
    "e164_number": "+15551234567",
    "routing_target_type": "agent",
    "routing_target_id": "AGENT_UUID"
  }'
```

### Dynamic routing (server URL)

Route calls to a webhook that decides which agent to use:

```bash
curl -X POST http://localhost:8090/v1/phone-numbers \
  -H "Authorization: Bearer tc_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "external_number_sid": "PNxxxxxxxx",
    "e164_number": "+15551234567",
    "routing_target_type": "webhook",
    "server_url": "https://your-server.com/turncall-events"
  }'
```

See [Call Init](/guides/call-init) for details on how dynamic routing works.

### Telnyx numbers

A Telnyx number answers inbound calls through Telnyx Call Control. Bind it with
`"carrier": "telnyx"`; `external_number_sid` is its Telnyx phone number id:

```bash
curl -X POST http://localhost:8090/v1/phone-numbers \
  -H "Authorization: Bearer tc_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "carrier": "telnyx",
    "external_number_sid": "1293384261075731499",
    "e164_number": "+15551234567",
    "routing_target_type": "agent",
    "routing_target_id": "AGENT_UUID"
  }'
```

Then, in Telnyx Mission Control, set the webhook URL of the number's Call
Control application to `https://<your host>/webhooks/telnyx/voice` (TurnCall
does not configure it for you yet, so `twilio_webhooks_configured` reads
`false`). The agent, its tools, recording, ambience and voicemail detection
behave exactly as on a Twilio number.

The Telnyx account is the platform's `TELNYX_API_KEY` and `TELNYX_PUBLIC_KEY`,
or the project's own:

```bash
curl -X PUT http://localhost:8090/v1/credentials/telnyx \
  -H "Authorization: Bearer tc_xxx" \
  -H "Content-Type: application/json" \
  -d '{"api_key": "KEY...", "public_key": "<base64 public key>"}'
```

The public key (Mission Control > Keys & Credentials > Public Key) is how
TurnCall knows a webhook came from your Telnyx account: every webhook is
checked against it, and one that is unsigned, signed by another key, or more
than five minutes old is refused. With no API key anywhere, a call to the
number fails before it is answered, and the call's `error.raised` event carries
`missing_keys: ["telnyx"]`.

Cold and warm transfers and sending DTMF work on a Telnyx number as on Twilio (see
[Call transfer](/guides/tools#call-transfer-cold-warm)). Not yet on Telnyx:
outbound calls. SMS on Telnyx numbers is not supported, so `sms_enabled` is
refused on one.

### Bring your own Twilio account

A number can run on its own Twilio account instead of the platform's
`TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN`. Send the pair — both or neither —
and `external_number_sid` becomes optional: TurnCall looks the number up on that
account, which is also what proves the account owns it.

```bash
curl -X POST http://localhost:8090/v1/phone-numbers \
  -H "Authorization: Bearer tc_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "e164_number": "+15551234567",
    "twilio_account_sid": "ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "twilio_auth_token": "your-auth-token",
    "routing_target_type": "agent",
    "routing_target_id": "AGENT_UUID"
  }'
```

- Credentials that Twilio rejects, or that do not own the number, are a `422` —
  nothing is bound.
- The token is stored encrypted under `CREDENTIAL_ENCRYPTION_KEY` and never
  returned. Reads carry `twilio_account_sid` and `twilio_credentials`
  (`number` or `platform`).
- Every Twilio operation for that number uses its account: webhook
  configuration, outbound calls, hang-up, transfer, DTMF, recording download,
  and the signature check on its inbound webhooks (matched by the webhook's
  `AccountSid`).
- `PUT /v1/phone-numbers/{id}` with a new pair replaces it — rotating a token.
  Omitting the pair keeps the stored one.

<Note>
  With no platform Twilio account configured, an inbound webhook TurnCall cannot
  verify passes only while no number carries its own account (a development
  setup). Once any does, an unverifiable webhook is refused.
</Note>

Binding with a `server_url` returns a `server_url_secret` — TurnCall signs each call-init request with it so your endpoint can verify the source.

## Update a Binding

Re-route a number in place — the phone id and its `server_url_secret` stay stable, so a call-init endpoint keeps verifying with the same secret across edits:

```bash
curl -X PUT http://localhost:8090/v1/phone-numbers/PHONE_UUID \
  -H "Authorization: Bearer tc_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "routing_target_type": "agent",
    "routing_target_id": "OTHER_AGENT_UUID",
    "sms_enabled": true
  }'
```

A secret is minted only when `server_url` appears on a number that never had one; it is never rotated implicitly.

## Configure Twilio

TurnCall sets these on bind when `PUBLIC_BASE_URL` is configured (the response
says so in `twilio_webhooks_configured`). To set them by hand:

- **Voice URL**: `https://your-host/webhooks/twilio/voice/inbound` (POST)
- **Status URL**: `https://your-host/webhooks/twilio/status` (POST)

## SMS Support

Enable SMS on a phone number to handle both voice calls and text messages:

```json
{
  "sms_enabled": true
}
```

When `sms_enabled: true` is set on bind, TurnCall auto-configures the Twilio SMS webhook. See [SMS / Chat](/guides/sms-chat) for details.

## WhatsApp Support

Enable WhatsApp on a phone number:

```json
{
  "whatsapp_enabled": true
}
```

See [WhatsApp](/guides/whatsapp) for full setup instructions.
