Your server hears from TurnCall in two ways:

- **call-init** — a request TurnCall makes to your server URL before a call starts. Your answer picks the agent and fills its variables. It is the only event sent to a server URL.
- **webhook events** — everything that happens during and after a call (transcripts, tool results, transfers, failovers, the end of the call), delivered to the URLs you subscribe with `POST /v1/webhooks`. They are fire-and-forget: your response is ignored.

## call-init

Bind a phone number with `routing_target_type: "webhook"`:

```bash
curl -X POST http://localhost:8090/v1/phone-numbers \
  -H "Authorization: Bearer tc_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "external_number_sid": "PNxxx",
    "e164_number": "+15551234567",
    "routing_target_type": "webhook",
    "server_url": "https://your-server.com/turncall-events"
  }'
```

A WebRTC call takes `server_url` in the body of `POST /v1/webrtc/connect` instead. The request and the answer are described in [call-init](/guides/call-init).

## Webhook events

```bash
curl -X POST http://localhost:8090/v1/webhooks \
  -H "Authorization: Bearer tc_xxx" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://your-server.com/events", "events": ["*"]}'
```

`events` is a list of event types, or `["*"]` for all of them. The response carries the signing secret, once. To change the list later without changing the secret, use `PATCH /v1/webhooks/{id}` with a new `events`.

Every delivery is one envelope:

```json
{
  "event": "transcript.final",
  "project_id": "uuid",
  "call_id": "uuid",
  "agent_id": "uuid",
  "event_id": "uuid",
  "timestamp": "2026-10-12T17:40:43Z",
  "payload": {"role": "customer", "text": "Hello?"}
}
```

`event_id` is stable across retries: use it to drop a redelivery.

| Event | When |
|-------|------|
| `call.initializing` | The call is created, after call-init |
| `call.started` | The agent is about to answer |
| `transcript.final` | Each final utterance, the caller's or the agent's |
| `tool.result` | A tool call returned |
| `call.transferred` / `transfer.answered` | A transfer started / the transfer target answered |
| `call.agent_handoff` | The call moved to another agent |
| `provider.failover` | An STT, LLM or TTS moved to its backup |
| `error.raised` | A stage failed; the payload says which and why |
| `call.customer_silent` / `call.max_duration_reached` / `call.opted_out` | The idle guard, the duration cap, or a do-not-call request ended the call |
| `dtmf.sent` / `context.injected` | Keypad tones sent / a message added to the live call |
| `recording.ready` | The recording is stored |
| `call.failed` | The call could not be connected |
| `call.ended` | The call is over — with transcript, analysis and `ended_reason` |
| `call.rejected` | An inbound call refused over the live-call limit (no `call_id`) |
| `session.created` / `session.updated` / `chat.created` | Text conversations |
| `eval.run.started` / `eval.run.completed` | Eval runs |
| `campaign.started` / `campaign.completed` / `campaign.cancelled` | Campaigns |

`metrics.turn` and `delegation.completed` are stored on the call's event log (`GET /v1/calls/{id}/events`) and never delivered.

Tool calls go to each tool's own `webhook_url` — see [Tools](/guides/tools).

If the project has [redaction](/guides/redaction) on, every payload is redacted before it is sent: a caller's number reads `<PHONE_NUMBER>`, and so do `from_number` and `to_number`. What was redacted is not recoverable from the webhook or the event log; the call record (`GET /v1/calls/{id}`) keeps the numbers. call-init and tool webhooks are part of the live call and are never redacted.

`call.ended` carries the call's `retention`: how many days its recording, transcript and events are kept, `null` for good. See [Retention](/guides/retention).

## Signature Verification

All server events include HMAC-SHA256 signatures:

```
X-TurnCall-Signature: v1=<hex_hmac>
X-TurnCall-Timestamp: 1712345678
```

Verify by computing HMAC-SHA256 over `"timestamp.body"` with the signing secret: for call-init, the one returned when you bound the phone number; for webhook events, the one returned when you created the subscription.
