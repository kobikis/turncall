TurnCall supports multiple providers for each stage of the voice pipeline. Configure them per-agent.

## Provider Matrix

| Role | Providers |
|------|-----------|
| **STT** | `deepgram` (default, streaming), `openai`, `elevenlabs`, `cartesia` (Ink, streaming), `assemblyai` (Universal-Streaming) |
| **LLM** | `openai` (default), `anthropic` (Claude), `google` (Gemini), `ollama` (local), `custom_openai` (any OpenAI-compatible), `openrouter` (multi-model + fallback routing, voice only), `bedrock` (AWS-hosted Anthropic / Meta / Mistral / Amazon models) |
| **TTS** | `deepgram` (default), `openai`, `elevenlabs`, `cartesia` (Sonic-3.6, streaming, 60+ emotions) |
| **S2S** | `openai` (Realtime API — optional `base_url` targets an OpenAI-Realtime gateway like Vercel AI Gateway / LiteLLM / xAI, e.g. Grok), `openai_live` (GPT-Live-1, full duplex), `google` (Gemini Live), `aws` (Amazon Nova Sonic 2) |

## STT Configuration

<CodeGroup>
```json Deepgram (default)
"stt": {"provider": "deepgram", "model": "nova-3-general", "language": "en"}
```

```json OpenAI
"stt": {"provider": "openai", "model": "gpt-transcribe"}
```

```json ElevenLabs Scribe
"stt": {"provider": "elevenlabs"}
```

```json Cartesia Ink
"stt": {"provider": "cartesia"}
```

```json AssemblyAI Universal-Streaming
"stt": {"provider": "assemblyai"}
```
</CodeGroup>

### STT Options

| Field | Required | Description |
|-------|----------|-------------|
| `provider` | No | `deepgram` (default), `openai`, `elevenlabs`, `cartesia`, `assemblyai` |
| `model` | No | Leave unset for the provider's own default: `nova-3-general` (Deepgram), `gpt-transcribe` (OpenAI — its predecessor `gpt-4o-transcribe` is withdrawn on 2027-02-26), `scribe_v1` (ElevenLabs), `ink-whisper` (Cartesia), `universal-streaming-english` (AssemblyAI — `universal-streaming-multilingual` when `language` is not English) |
| `language` | No | BCP-47 code (default `en`) |
| `keyterms` | No | Vocabulary hints — product names, SKUs, surnames. One list, mapped to each provider's own spelling. See [Keyterms](#keyterms) |
| `extra` | No | Passthrough to the provider. Keys naming a setting TurnCall already manages — `model`, `language`, and Deepgram's `punctuate` / `smart_format` / `interim_results` — are ignored so they cannot silently override your config |

On Deepgram, `extra` reaches the full transcription surface: `profanity_filter`,
`diarize`, `redact`, `version`, `utterance_end_ms`.

On AssemblyAI, `extra` reaches its streaming settings by name — `domain`
(`medical-v1`), `min_turn_silence`, `format_turns`, and on Universal-3 Pro
models `mode`, `voice_focus`, `language_codes`. A key AssemblyAI has no setting
for is logged as ignored rather than silently dropped.

AssemblyAI splits its streaming models by language rather than taking a
`language` parameter. With no `model`, an English agent gets
`universal-streaming-english` and any other gets
`universal-streaming-multilingual`, which covers English, Spanish, German,
French, Portuguese and Italian — the English model given Spanish transcribes
it as English words, with no error to say so. For other languages, name a
Universal-3 Pro model (`universal-3-6-pro`), which costs about three times as
much.

### Keyterms

Words a general model mishears — product names, SKUs, surnames — go in
`stt.keyterms` as one list. TurnCall maps it to whatever the chosen provider
calls it.

```json
"stt": {"provider": "deepgram", "keyterms": ["Xhosa", "Kubernetes", "Nguyen"]}
```

| Provider | Sent as | Notes |
|----------|---------|-------|
| Deepgram | `keyterm` on `nova-3*` / `flux*`, `keywords` on older models | Deepgram **400s** on the wrong one rather than ignoring it |
| OpenAI | `keywords` | |
| ElevenLabs | `keyterms` | |
| Cartesia | `keyterm` | Honored on `ink-2*` / `ink-preview*` only; capped at 100 terms / 1200 characters per connection, truncated past that with a warning |
| AssemblyAI | `keyterms_prompt` | AssemblyAI refuses a session with more than 100, so the first 100 are sent, with a warning. Terms over 50 characters are ignored by AssemblyAI |

Blanks and duplicates are dropped when the agent is created.

<Warning>
  Don't hand-write `extra: {"keyterm": [...]}` on Deepgram. Which spelling is
  correct depends on the model — a Nova-2 agent sent `keyterm` gets
  `INVALID_QUERY_PARAMETER` and the call dies at connect. `keyterms` picks the
  right one for you, and takes precedence over the same key in `extra`.
</Warning>

<Note>
**Transcripts are not profanity-filtered by default.** Deepgram's filter
rewrites the words it matches rather than tagging them, so one false positive
silently alters a transcript you store, analyse and receive in `call.ended`.
Set `"extra": {"profanity_filter": true}` if you want it on.
</Note>

## LLM Configuration

<CodeGroup>
```json OpenAI (default)
"llm": {"provider": "openai", "model": "gpt-4o-mini"}
```

```json Anthropic Claude
"llm": {"provider": "anthropic", "model": "claude-sonnet-4-20250514"}
```

```json Google Gemini
"llm": {"provider": "google", "model": "gemini-3.6-flash"}
```

```json Ollama (local)
"llm": {"provider": "ollama", "model": "gemma3:12b"}
```

```json Custom OpenAI-compatible
"llm": {
  "provider": "custom_openai",
  "model": "meta-llama/Llama-3-70b",
  "base_url": "https://api.together.xyz/v1",
  "api_key": "your-key"
}
```

```json OpenRouter (model fallback)
"llm": {
  "provider": "openrouter",
  "model": "anthropic/claude-3.5-sonnet",
  "fallback_models": ["openai/gpt-4o", "google/gemini-flash-1.5"]
}
```

```json AWS Bedrock
"llm": {
  "provider": "bedrock",
  "model": "us.anthropic.claude-haiku-4-5-20251001-v1:0"
},
"aws": {"region": "us-west-2"}
```
</CodeGroup>

<Note>
  **OpenRouter** routes through [openrouter.ai](https://openrouter.ai) with automatic failover — if the primary model rate-limits or errors mid-call, it falls over to the next model in `fallback_models`. Voice only (WebRTC / Twilio / WhatsApp voice); not supported on the SMS/Chat text path. The model that answered each turn is recorded on `transcript.final` events.
</Note>

### LLM Options

| Field | Required | Description |
|-------|----------|-------------|
| `provider` | Yes | `openai`, `anthropic`, `google`, `ollama`, `custom_openai`, `openrouter`, or `bedrock` |
| `model` | Depends | Optional on `openai` (`gpt-4o-mini`), `anthropic` (`claude-sonnet-5`) and `google` (`gemini-3.6-flash`), which have a house model. **Required** on `ollama`, `custom_openai`, `bedrock` and `openrouter` — see below |
| `base_url` | For `custom_openai` | OpenAI-compatible API base URL |
| `api_key` | No | API key for `custom_openai` (masked in responses) |
| `fallback_models` | For `openrouter` | Ordered list of fallback models (voice only) |
| `temperature` | No | 0.0–2.0 (default: 0.7). **Not sent to `anthropic`** — current Claude models reject it and the call fails; set one via `llm.extra` if your model still accepts it. **Not sent to Gemini 3 models on `google`** — Google warns they loop below their own default of 1.0; older Gemini models still get it, and `llm.extra` sets one anyway |
| `max_tokens` | No | 1–128000 (default: 1024) |
| `warm_up` | No | `true` sends a one-token request with the system prompt as the caller's first turn starts, so the first reply does not wait on a cold connection. Voice only, OpenAI-compatible providers only (`openai`, `openrouter`, `custom_openai`, `ollama`); costs the system prompt's tokens once more per call. Default `false` |
| `extra` | No | Provider passthrough. On `bedrock` it becomes `additionalModelRequestFields` — how Anthropic extended thinking is reached. On `google` it merges into the generation config, e.g. `{"thinkingConfig": {"thinkingLevel": "low"}}` |

<Warning>
  **`ollama`, `custom_openai`, `bedrock` and `openrouter` reject an agent with
  no `llm.model`** — creating one returns `422`. There is no sensible default
  to pick: on those four the model *is* the deployment, so a guess would
  either 404 at the provider or quietly run a model you didn't choose. Failing
  at create beats failing mid-call.
</Warning>

## TTS Configuration

<CodeGroup>
```json Deepgram (default)
"tts": {"provider": "deepgram", "voice": "aura-2-helena-en"}
```

```json OpenAI
"tts": {"provider": "openai", "voice": "alloy"}
```

```json ElevenLabs
"tts": {"provider": "elevenlabs", "voice": "rachel"}
```

```json Cartesia Sonic
"tts": {"provider": "cartesia", "model": "sonic-3.6", "voice": "<cartesia-voice-id>"}
```
</CodeGroup>

### TTS Options

| Field | Required | Description |
|-------|----------|-------------|
| `provider` | No | `deepgram` (default), `openai`, `elevenlabs`, `cartesia` |
| `model` | No | Provider default when unset: `aura-2-helena-en`, `tts-1`, `eleven_flash_v2_5`, `sonic-3.6` |
| `voice` | No | Provider default when unset: `aura-2-helena-en`, `alloy`, `Rachel`. Cartesia voice ids are account-specific, so there is no default — set one |
| `speed` | No | 0.25–4.0 (default 1.0, which sends nothing). Honoured by Deepgram (0.7–1.5), OpenAI and ElevenLabs |
| `pronunciations` | No | Word → IPA map for words the voice says wrong. One spelling, each provider's own markup generated from it. See [Pronunciations](#pronunciations) |
| `extra` | No | Passthrough to the provider. Keys naming a setting TurnCall already manages — `model`, `voice`, `speed`, and Cartesia's `language` / `emotion` — are ignored so they cannot silently override your config |

<Note>
Each provider falls back to **its own** model and voice. Earlier versions leaked
a Deepgram voice name into the other three, so an agent that chose Cartesia,
OpenAI or ElevenLabs without naming a model and voice was misconfigured.
</Note>

### Pronunciations

Words a voice says wrong — drug names, surnames, SKUs — go in
`tts.pronunciations` as one flat word → IPA map. One IPA spelling works
everywhere, because each provider's markup is generated from it. The outbound
mirror of [`stt.keyterms`](#keyterms).

```json
"tts": {
  "provider": "cartesia",
  "model": "sonic-3.6",
  "pronunciations": {"Metformin": "mɛtˈfɔɹmɪn", "Nguyen": "ˈwɪn"}
}
```

| Provider | Markup generated |
|----------|------------------|
| Cartesia | Inline phonemes |
| ElevenLabs | SSML `<phoneme>` — needs a phoneme-capable model, see below |
| Deepgram | Inline pronunciation object |
| OpenAI | None. It has no pronunciation surface, so the map is inert |

The value must be **real IPA**. `{"Metformin": "met-FOR-min"}` is a `422` naming
the word: pipecat's IPA helpers normalize and tokenize but never reject, so a
respelling would be accepted, inserted into the markup, and change nothing you
can hear. `/…/` and `[…]` wrappers are stripped and the value stored
canonically, so two spellings of one pronunciation are one config. Blanks are
dropped, and an empty map is the same as not setting one.

<Note>
**ElevenLabs needs a phoneme-capable model.** Pipecat reads `<phoneme>` tags only
on the models in its own `ELEVENLABS_PHONEME_MODELS` set, and only with
`enable_ssml_parsing` — a constructor argument no `tts.extra` can reach.
TurnCall passes it for exactly the agents that have pronunciations *and* such a
model, never for everyone: SSML parsing changes how **all** of that agent's text
is read. Your model is never downgraded for you.
</Note>

On a voice that cannot read the markup, the markup is **withheld** rather than
sent anyway: a `<phoneme>` tag reaching a service that is not parsing SSML is
read out loud, measured at 3.5–4.3× the audio. One unusable word is spoken as
written; it never silences the reply.

Whether the built voice can read the markup depends on the model, which an author
changes after the pronunciations are written — so it is a **warning**, never a
refusal. That, and a "pronunciation" that is the word typed back at us, come
back as [warnings on an agent read](/guides/agents#warnings-on-a-read).

<Warning>
  Cascade only. An S2S agent has no TTS stage for the markup to apply to, so the
  field is ignored and the agent read says so.
</Warning>

### Emotion on Cartesia

`tts.extra.emotion` sets one emotion for the whole call. To change it sentence
by sentence, have the model write Cartesia's inline tags — tell it in the
system prompt, e.g. *"Start a sentence with `<emotion value="excited"/>` when
you are excited; use only: excited, content, sympathetic, curious, calm."*
Sonic-3 reads `emotion`, `speed`, `volume`, `break` and `spell` tags; the full
emotion list is in Cartesia's docs, and an emotion only works when the words
agree with it.

Only a Cartesia voice gets the tags. Every other voice — a Deepgram backup in
`tts.failover` included — would read them aloud, so they are removed before
they reach it, and they are never written to the transcript.

## Failover

`stt.failover`, `llm.failover` and `tts.failover` each list backup providers,
in order, for a voice call. Every entry is a whole config of that role,
validated the same way — its own model, voice, language, keyterms or
pronunciations; nothing is inherited from the primary.

```json
{
  "stt": {"provider": "deepgram", "failover": [{"provider": "openai"}]},
  "tts": {
    "provider": "elevenlabs",
    "voice": "Rachel",
    "failover": [{"provider": "deepgram", "voice": "aura-2-helena-en"}]
  }
}
```

When the active provider reports an error that leaves it unusable — a refused
key, an unknown model or voice — the call moves to the next entry and carries
on. The backup STT is handed what the caller had just said and nobody
transcribed; the backup TTS speaks the reply that was cut off, from its start.
A recoverable error (a rate limit, a timeout) does not switch, and a call never
switches back, so the caller hears the voice change at most once per backup.

Each switch is a `provider.failover` call event `{role, from, to, error}` and an
entry in `failovers` on `call.ended` and the call read. Backups need keys like
any provider: a missing one is reported before the call starts.

<Note>
  Cascade only — a speech-to-speech agent hears and speaks for itself, so
  `stt.failover` and `tts.failover` are refused (422). An STT group cannot mix
  Deepgram Flux (`flux-*`) with other models: Flux decides when the caller's
  turn ends and the others do not.
</Note>

## AWS Bedrock

Bedrock is a *gateway*, not a vendor: `provider: "bedrock"` with
`model: "anthropic.claude-..."` names two different companies, and the same
Claude model is reachable through either `anthropic` or `bedrock` with
different credentials.

Model ids pass through verbatim in any of the three forms AWS accepts:

| Form | Example |
|------|---------|
| Direct | `amazon.nova-pro-v1:0` |
| Cross-region inference profile | `us.anthropic.claude-haiku-4-5-20251001-v1:0` |
| Provisioned throughput | `arn:aws:bedrock:us-east-1:123456789012:provisioned-model/abc` |

<Warning>
  **Most newer Anthropic models cannot be invoked by their bare id** — they
  require a cross-region inference profile, and fail with *"Invocation of model
  ID … with on-demand throughput isn't supported"*. Add the geography prefix
  matching your region (`us.`, `eu.`, `apac.`). Amazon's own `amazon.nova-*`
  models invoke fine directly.
</Warning>

<Warning>
  Model availability is **region-specific**, and access is granted per model per
  region in the Bedrock console. A valid-looking model id in the wrong region
  fails at call time with `AccessDeniedException` or `ValidationException` —
  TurnCall's error names both the model and the region so you can tell which
  half is wrong.
</Warning>

### Credentials

Bedrock and Nova Sonic share one `aws` block on the agent config, so an agent's
LLM and voice leg always authenticate as the same principal. Credentials are
resolved by the **server**, in this order:

| Source | Config | Notes |
|--------|--------|-------|
| Assume role | `aws.role_arn` (+ optional `aws.external_id`) | Preferred for multi-tenant setups — yields temporary credentials, stores no secret |
| Static keys | `aws.access_key_id` + `aws.secret_access_key` | Off by default, see below |
| Named profile | `aws.profile` | How an SSO login is selected |
| Project credential | `PUT /v1/credentials/aws` | Used when the agent's block names no source of its own — see [Project credentials](#project-credentials) |
| Ambient chain | *(nothing set)* | Env vars, SSO cache, EC2 instance profile, ECS task role, EKS IRSA |

```json
"aws": {
  "region": "us-west-2",
  "role_arn": "arn:aws:iam::123456789012:role/turncall-bedrock"
}
```

| Field | Required | Description |
|-------|----------|-------------|
| `region` | No | Defaults to `AWS_REGION`. Set it explicitly — that variable also points at the S3 bucket |
| `role_arn` | No | IAM role assumed per call |
| `external_id` | No | `ExternalId` for the assume-role call |
| `access_key_id` | No | Requires `AWS_AGENT_CREDENTIALS_ENABLED=true` |
| `secret_access_key` | No | Masked in API responses |
| `session_token` | No | For temporary credentials. Masked in API responses |
| `profile` | No | Named profile resolved from the host's AWS config |

<Warning>
  **Per-agent static keys are disabled by default.** They persist in the agent
  config, which is not encrypted at rest, and an AWS key is materially worse to
  leak than a vendor API key. Agents supplying them are rejected at create
  unless `AWS_AGENT_CREDENTIALS_ENABLED=true`. Prefer `role_arn`, which stores
  no durable secret.
</Warning>

<Note>
  **SSO is a workstation mechanism.** `aws sso login` is an interactive browser
  flow a server cannot perform, and its cached token expires. It works for local
  development via `aws.profile` or the ambient chain; in production use an
  instance profile, IRSA, or `role_arn`.
</Note>

See `adr/0016-bedrock-and-nova-sonic.md`
for why credentials are resolved this way.

## API keys

Every provider key resolves in one order, everywhere a project's work runs —
voice calls, chat/SMS/WhatsApp turns, post-call analysis and takeaways, the
transfer briefing, knowledge-base embeddings and the eval judge:

1. **The agent's own key** — `llm.api_key` (or the agent's `aws` block).
2. **The project's credential** — see [Project credentials](#project-credentials).
3. **The platform environment** — the variables below.

So a deployment can keep every key in its environment, none at all with each
project bringing its own, or any mix. Keys are read fresh for every call and
every message: a credential written a moment ago is the one the next call uses,
with no restart.

### Platform environment

| Provider | Environment Variable |
|----------|---------------------|
| Deepgram | `DEEPGRAM_API_KEY` |
| OpenAI | `OPENAI_API_KEY` |
| Anthropic | `ANTHROPIC_API_KEY` |
| ElevenLabs | `ELEVENLABS_API_KEY` |
| Cartesia | `CARTESIA_API_KEY` |
| AssemblyAI | `ASSEMBLYAI_API_KEY` |
| Google (Gemini) | `GOOGLE_API_KEY` |
| OpenRouter | `OPENROUTER_API_KEY` |
| HeyGen (video avatar) | `HEYGEN_LIVE_AVATAR_API_KEY` |
| Tavus (video avatar) | `TAVUS_API_KEY` |
| AWS (Bedrock / Nova Sonic) | *No key* — see [Credentials](#credentials). `AWS_REGION` sets the default region |

| TypeSafe (Jev eval judge) | `TYPESAFE_API_KEY` |

<Info>
  Ollama requires no API key — just install it locally and run `ollama pull <model>`.
  `custom_openai` sends only the agent's own `llm.api_key` (falling back to
  `OPENAI_API_KEY`); a project's OpenAI credential is never sent to an endpoint
  the agent names itself.
</Info>

### Project credentials

A project can hold its own key per provider **account** — one Deepgram key
serves both transcription and voice, one OpenAI key serves STT, LLM, TTS, S2S
and the eval judge. Keys are encrypted at rest under `CREDENTIAL_ENCRYPTION_KEY`
and never returned by any read.

```bash
# Store (or replace) — takes effect on the next call
curl -X PUT http://localhost:8090/v1/credentials/deepgram \
  -H "Authorization: Bearer tc_xxx" -H "Content-Type: application/json" \
  -d '{"api_key": "dg_..."}'

# AWS takes the agent aws block's shape instead
curl -X PUT http://localhost:8090/v1/credentials/aws \
  -H "Authorization: Bearer tc_xxx" -H "Content-Type: application/json" \
  -d '{"role_arn": "arn:aws:iam::123456789012:role/turncall", "region": "us-west-2"}'

curl http://localhost:8090/v1/credentials -H "Authorization: Bearer tc_xxx"          # presence only
curl -X DELETE http://localhost:8090/v1/credentials/deepgram -H "Authorization: Bearer tc_xxx"
```

| Account | Serves |
|---------|--------|
| `openai` | STT, LLM, TTS, S2S (`openai`, `openai_live`), eval judge |
| `anthropic` | LLM, eval judge |
| `openrouter` | LLM |
| `google` | LLM, S2S (Gemini Live) |
| `deepgram`, `elevenlabs`, `cartesia` | STT, TTS |
| `assemblyai` | STT |
| `heygen`, `tavus` | Video avatar |
| `aws` | Bedrock LLM, Nova Sonic S2S |
| `typesafe` | Eval judge (`jev`) |
| `telnyx` | Telnyx numbers (`carrier` role) — takes `{"api_key", "public_key"}`, see [Telnyx numbers](/guides/phone-numbers#telnyx-numbers) |
| `asterisk` | A PBX's Asterisk, over ARI (`carrier` role) — `{ari_url, username, password}`, see [Asterisk numbers](/guides/phone-numbers#asterisk-numbers) |

Deleting a credential is idempotent and returns the project to the platform key.
An `aws` project credential is **not** gated by `AWS_AGENT_CREDENTIALS_ENABLED`
— that flag governs static keys inside agent config only, because those are
the ones stored unencrypted.

`GET /v1/providers` lists the valid providers per role and, per account, two
separate signals: `platform_key` (the environment has one) and
`project_credential` (this project has one). Together they say whether removing
a credential falls back or ends in failed calls.

### When a key is missing or refused

Before a call is built, TurnCall checks every provider the agent uses (STT, LLM
and TTS, or the S2S provider, plus the avatar) against all three levels. If one
has no key anywhere, the call is refused before it rings through: it ends
`failed` / `pipeline_error` with an `error.raised` event carrying
`missing_keys`, and `POST /v1/webrtc/connect` answers
`500 pipeline_start_failed` with `details.missing_keys`. AWS is not checked,
since its ambient credential chain is not a key TurnCall can see. Neither are
`ollama` and `custom_openai`, which have no account.

A key that exists but is wrong is only found out when the provider refuses it,
partway into the call. That call ends the same way, with `provider` and
`key_rejected: true` on the event. See
[When a call fails](/guides/post-call-analysis#when-a-call-fails).

<Warning>
  `CREDENTIAL_ENCRYPTION_KEY` is set once. Rotating it orphans every stored
  credential, and the service refuses to start when credentials exist and the
  key is unset or wrong. Generate one with
  `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
</Warning>
