TurnCall supports multiple providers for each stage of the voice pipeline. Configure them per-agent.

## Provider Matrix

| Role | Providers |
|------|-----------|
| **STT** | `deepgram` (default, streaming), `openai`, `elevenlabs`, `cartesia` (Ink, streaming) |
| **LLM** | `openai` (default), `anthropic` (Claude), `ollama` (local), `custom_openai` (any OpenAI-compatible), `openrouter` (multi-model + fallback routing, voice only), `bedrock` (AWS-hosted Anthropic / Meta / Mistral / Amazon models) |
| **TTS** | `deepgram` (default), `openai`, `elevenlabs`, `cartesia` (Sonic-3.6, streaming, 60+ emotions) |
| **S2S** | `openai` (Realtime API — optional `base_url` targets an OpenAI-Realtime gateway like Vercel AI Gateway / LiteLLM / xAI, e.g. Grok), `openai_live` (GPT-Live-1, full duplex), `google` (Gemini Live), `aws` (Amazon Nova Sonic 2) |

## STT Configuration

<CodeGroup>
```json Deepgram (default)
"stt": {"provider": "deepgram", "model": "nova-3-general", "language": "en"}
```

```json OpenAI
"stt": {"provider": "openai", "model": "gpt-transcribe"}
```

```json ElevenLabs Scribe
"stt": {"provider": "elevenlabs"}
```

```json Cartesia Ink
"stt": {"provider": "cartesia"}
```
</CodeGroup>

### STT Options

| Field | Required | Description |
|-------|----------|-------------|
| `provider` | No | `deepgram` (default), `openai`, `elevenlabs`, `cartesia` |
| `model` | No | Leave unset for the provider's own default: `nova-3-general` (Deepgram), `gpt-transcribe` (OpenAI — its predecessor `gpt-4o-transcribe` is withdrawn on 2027-02-26), `scribe_v1` (ElevenLabs), `ink-whisper` (Cartesia) |
| `language` | No | BCP-47 code (default `en`) |
| `keyterms` | No | Vocabulary hints — product names, SKUs, surnames. One list, mapped to each provider's own spelling. See [Keyterms](#keyterms) |
| `extra` | No | Passthrough to the provider. Keys naming a setting TurnCall already manages — `model`, `language`, and Deepgram's `punctuate` / `smart_format` / `interim_results` — are ignored so they cannot silently override your config |

On Deepgram, `extra` reaches the full transcription surface: `profanity_filter`,
`diarize`, `redact`, `version`, `utterance_end_ms`.

### Keyterms

Words a general model mishears — product names, SKUs, surnames — go in
`stt.keyterms` as one list. TurnCall maps it to whatever the chosen provider
calls it.

```json
"stt": {"provider": "deepgram", "keyterms": ["Xhosa", "Kubernetes", "Nguyen"]}
```

| Provider | Sent as | Notes |
|----------|---------|-------|
| Deepgram | `keyterm` on `nova-3*` / `flux*`, `keywords` on older models | Deepgram **400s** on the wrong one rather than ignoring it |
| OpenAI | `keywords` | |
| ElevenLabs | `keyterms` | |
| Cartesia | `keyterm` | Honored on `ink-2*` / `ink-preview*` only; capped at 100 terms / 1200 characters per connection, truncated past that with a warning |

Blanks and duplicates are dropped when the agent is created.

<Warning>
  Don't hand-write `extra: {"keyterm": [...]}` on Deepgram. Which spelling is
  correct depends on the model — a Nova-2 agent sent `keyterm` gets
  `INVALID_QUERY_PARAMETER` and the call dies at connect. `keyterms` picks the
  right one for you, and takes precedence over the same key in `extra`.
</Warning>

<Note>
**Transcripts are not profanity-filtered by default.** Deepgram's filter
rewrites the words it matches rather than tagging them, so one false positive
silently alters a transcript you store, analyse and receive in `call.ended`.
Set `"extra": {"profanity_filter": true}` if you want it on.
</Note>

## LLM Configuration

<CodeGroup>
```json OpenAI (default)
"llm": {"provider": "openai", "model": "gpt-4o-mini"}
```

```json Anthropic Claude
"llm": {"provider": "anthropic", "model": "claude-sonnet-4-20250514"}
```

```json Ollama (local)
"llm": {"provider": "ollama", "model": "gemma3:12b"}
```

```json Custom OpenAI-compatible
"llm": {
  "provider": "custom_openai",
  "model": "meta-llama/Llama-3-70b",
  "base_url": "https://api.together.xyz/v1",
  "api_key": "your-key"
}
```

```json OpenRouter (model fallback)
"llm": {
  "provider": "openrouter",
  "model": "anthropic/claude-3.5-sonnet",
  "fallback_models": ["openai/gpt-4o", "google/gemini-flash-1.5"]
}
```

```json AWS Bedrock
"llm": {
  "provider": "bedrock",
  "model": "us.anthropic.claude-haiku-4-5-20251001-v1:0"
},
"aws": {"region": "us-west-2"}
```
</CodeGroup>

<Note>
  **OpenRouter** routes through [openrouter.ai](https://openrouter.ai) with automatic failover — if the primary model rate-limits or errors mid-call, it falls over to the next model in `fallback_models`. Voice only (WebRTC / Twilio / WhatsApp voice); not supported on the SMS/Chat text path. The model that answered each turn is recorded on `transcript.final` events.
</Note>

### LLM Options

| Field | Required | Description |
|-------|----------|-------------|
| `provider` | Yes | `openai`, `anthropic`, `ollama`, `custom_openai`, `openrouter`, or `bedrock` |
| `model` | Depends | Optional on `openai` (`gpt-4o-mini`) and `anthropic` (`claude-sonnet-5`), which have a house model. **Required** on `ollama`, `custom_openai`, `bedrock` and `openrouter` — see below |
| `base_url` | For `custom_openai` | OpenAI-compatible API base URL |
| `api_key` | No | API key for `custom_openai` (masked in responses) |
| `fallback_models` | For `openrouter` | Ordered list of fallback models (voice only) |
| `temperature` | No | 0.0–2.0 (default: 0.7). **Not sent to `anthropic`** — current Claude models reject it and the call fails; set one via `llm.extra` if your model still accepts it |
| `max_tokens` | No | 1–128000 (default: 1024) |
| `extra` | No | Provider passthrough. On `bedrock` it becomes `additionalModelRequestFields` — how Anthropic extended thinking is reached |

<Warning>
  **`ollama`, `custom_openai`, `bedrock` and `openrouter` reject an agent with
  no `llm.model`** — creating one returns `422`. There is no sensible default
  to pick: on those four the model *is* the deployment, so a guess would
  either 404 at the provider or quietly run a model you didn't choose. Failing
  at create beats failing mid-call.
</Warning>

## TTS Configuration

<CodeGroup>
```json Deepgram (default)
"tts": {"provider": "deepgram", "voice": "aura-2-helena-en"}
```

```json OpenAI
"tts": {"provider": "openai", "voice": "alloy"}
```

```json ElevenLabs
"tts": {"provider": "elevenlabs", "voice": "rachel"}
```

```json Cartesia Sonic
"tts": {"provider": "cartesia", "model": "sonic-3.6", "voice": "<cartesia-voice-id>"}
```
</CodeGroup>

### TTS Options

| Field | Required | Description |
|-------|----------|-------------|
| `provider` | No | `deepgram` (default), `openai`, `elevenlabs`, `cartesia` |
| `model` | No | Provider default when unset: `aura-2-helena-en`, `tts-1`, `eleven_flash_v2_5`, `sonic-3.6` |
| `voice` | No | Provider default when unset: `aura-2-helena-en`, `alloy`, `Rachel`. Cartesia voice ids are account-specific, so there is no default — set one |
| `speed` | No | 0.25–4.0 (default 1.0, which sends nothing). Honoured by Deepgram (0.7–1.5), OpenAI and ElevenLabs |
| `extra` | No | Passthrough to the provider. Keys naming a setting TurnCall already manages — `model`, `voice`, `speed`, and Cartesia's `language` / `emotion` — are ignored so they cannot silently override your config |

<Note>
Each provider falls back to **its own** model and voice. Earlier versions leaked
a Deepgram voice name into the other three, so an agent that chose Cartesia,
OpenAI or ElevenLabs without naming a model and voice was misconfigured.
</Note>

## AWS Bedrock

Bedrock is a *gateway*, not a vendor: `provider: "bedrock"` with
`model: "anthropic.claude-..."` names two different companies, and the same
Claude model is reachable through either `anthropic` or `bedrock` with
different credentials.

Model ids pass through verbatim in any of the three forms AWS accepts:

| Form | Example |
|------|---------|
| Direct | `amazon.nova-pro-v1:0` |
| Cross-region inference profile | `us.anthropic.claude-haiku-4-5-20251001-v1:0` |
| Provisioned throughput | `arn:aws:bedrock:us-east-1:123456789012:provisioned-model/abc` |

<Warning>
  **Most newer Anthropic models cannot be invoked by their bare id** — they
  require a cross-region inference profile, and fail with *"Invocation of model
  ID … with on-demand throughput isn't supported"*. Add the geography prefix
  matching your region (`us.`, `eu.`, `apac.`). Amazon's own `amazon.nova-*`
  models invoke fine directly.
</Warning>

<Warning>
  Model availability is **region-specific**, and access is granted per model per
  region in the Bedrock console. A valid-looking model id in the wrong region
  fails at call time with `AccessDeniedException` or `ValidationException` —
  TurnCall's error names both the model and the region so you can tell which
  half is wrong.
</Warning>

### Credentials

Bedrock and Nova Sonic share one `aws` block on the agent config, so an agent's
LLM and voice leg always authenticate as the same principal. Credentials are
resolved by the **server**, in this order:

| Source | Config | Notes |
|--------|--------|-------|
| Assume role | `aws.role_arn` (+ optional `aws.external_id`) | Preferred for multi-tenant setups — yields temporary credentials, stores no secret |
| Static keys | `aws.access_key_id` + `aws.secret_access_key` | Off by default, see below |
| Named profile | `aws.profile` | How an SSO login is selected |
| Ambient chain | *(nothing set)* | Env vars, SSO cache, EC2 instance profile, ECS task role, EKS IRSA |

```json
"aws": {
  "region": "us-west-2",
  "role_arn": "arn:aws:iam::123456789012:role/turncall-bedrock"
}
```

| Field | Required | Description |
|-------|----------|-------------|
| `region` | No | Defaults to `AWS_REGION`. Set it explicitly — that variable also points at the S3 bucket |
| `role_arn` | No | IAM role assumed per call |
| `external_id` | No | `ExternalId` for the assume-role call |
| `access_key_id` | No | Requires `AWS_AGENT_CREDENTIALS_ENABLED=true` |
| `secret_access_key` | No | Masked in API responses |
| `session_token` | No | For temporary credentials. Masked in API responses |
| `profile` | No | Named profile resolved from the host's AWS config |

<Warning>
  **Per-agent static keys are disabled by default.** They persist in the agent
  config, which is not encrypted at rest, and an AWS key is materially worse to
  leak than a vendor API key. Agents supplying them are rejected at create
  unless `AWS_AGENT_CREDENTIALS_ENABLED=true`. Prefer `role_arn`, which stores
  no durable secret.
</Warning>

<Note>
  **SSO is a workstation mechanism.** `aws sso login` is an interactive browser
  flow a server cannot perform, and its cached token expires. It works for local
  development via `aws.profile` or the ambient chain; in production use an
  instance profile, IRSA, or `role_arn`.
</Note>

See `adr/0016-bedrock-and-nova-sonic.md`
for why credentials are resolved this way.

## Required API Keys

| Provider | Environment Variable |
|----------|---------------------|
| Deepgram | `DEEPGRAM_API_KEY` |
| OpenAI | `OPENAI_API_KEY` |
| Anthropic | `ANTHROPIC_API_KEY` |
| ElevenLabs | `ELEVENLABS_API_KEY` |
| Cartesia | `CARTESIA_API_KEY` |
| Google (Gemini) | `GOOGLE_API_KEY` |
| OpenRouter | `OPENROUTER_API_KEY` |
| HeyGen (video avatar) | `HEYGEN_LIVE_AVATAR_API_KEY` |
| Tavus (video avatar) | `TAVUS_API_KEY` |
| AWS (Bedrock / Nova Sonic) | *No key* — see [Credentials](#credentials). `AWS_REGION` sets the default region |

<Info>
  Ollama requires no API key — just install it locally and run `ollama pull <model>`.
</Info>
