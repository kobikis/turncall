## ⚠️ Upgrade notes

**Set `CREDENTIAL_ENCRYPTION_KEY` before upgrading a database that holds a
secret.** The `seal_secrets_at_rest` migration (`e6c2a8f4b0d9`) encrypts webhook subscriptions'
signing secrets, numbers' `server_url_secret` and the secrets in agent configs
under it, and without it refuses to run and changes nothing. A deployment that
stores project credentials has it set already. From then on, creating a webhook
subscription, giving a number a `server_url`, saving an agent with a secret, or
taking a call or a text whose call-init answers with one needs the key too. Set
it once and never rotate it. Backups taken before the upgrade still hold the secrets in
plaintext. See [Compliance](/guides/compliance#the-controls).

**Move outbound URLs to `https://`, or set `ALLOW_PLAIN_HTTP_URLS`, on any
deployment that is not a development one.** Outside `TURNCALL_ENV=development`,
a plain `http://` URL is now refused with a `422` when a webhook subscription is
created, a number is bound or updated, or an agent is created or replaced,
unless its host ends in `.svc` or `.svc.cluster.local` (a Kubernetes Service in
the same cluster). Rows that already hold one keep being delivered to: startup
names them as `plain_http_stored`, per project and kind, and deliveries to them
log `plain_http_delivery`, at most once a minute per kind. Inline eval targets
and `turncall-demo` agent files are not refused. Agent and number `PUT` replace the whole
row, so editing one that still holds an `http://` URL is a `422` until the URL
is fixed. A WebRTC `server_url` over plain http is now refused in staging too,
not only in production. `ALLOW_PLAIN_HTTP_URLS=true` allows plain http
everywhere; `false` refuses it in development too. See
[Compliance](/guides/compliance#the-controls).

**Rebuild an image built on or after 2026-10-19.** TurnCall's pipecat requirement
allowed any 1.x, so an install or image made from that day on got pipecat
1.13.0, on which an S2S agent's handoff to its own LLM (delegation) breaks.
TurnCall now runs on pipecat 1.13 and holds it at `>=1.13.0,<1.14.0`, so a new
pipecat minor only arrives with a TurnCall release. See *pipecat 1.13* below.

## Added

**xAI Grok as an LLM.** Set `llm.provider` to `xai` to run Grok on voice calls
and text conversations, with tools, as a failover backup, and with warm-up. It
uses the same xAI account as Grok Voice; the key needs xAI's chat endpoint, and
a voice-only key is refused. An unset model is `grok-4.20-non-reasoning`. See
[Providers](/guides/providers).

**xAI speech-to-text.** Set `stt.provider` to `xai` for xAI's streaming
transcription, with keyterms. TurnCall asks xAI for the final transcript as soon
as the caller stops speaking, so it arrives about 0.2 s after speech. See
[Providers](/guides/providers).

**xAI voices.** Set `tts.provider` to `xai` for xAI's voices (`eve` by default).
`speed` must be between 0.7 and 1.5. xAI reads no pronunciation markup. A wrong
key is not reported as refused, so give an xAI voice a `tts.failover` backup.
See [Providers](/guides/providers).

**Search and buy numbers.** An admin key can search a Twilio account for
available numbers by country, area code and digits, buy one, and bind it with
the usual call; the purchase answers with what binding needs, and is recorded
in the audit log. It runs on the platform's Twilio account or on one you name.
See [Phone numbers](/guides/phone-numbers#search-and-buy-a-number).

**Search and buy numbers on Telnyx.** The same calls with `carrier: telnyx`
search and buy on the project's Telnyx account, with each number's price. A
purchase Telnyx has not finished within a few seconds answers `pending`; bind
the number once it lands on the account. If Telnyx does not answer the order,
the call says the order may have been placed: check the Telnyx portal before
buying again. See [Buying on Telnyx](/guides/phone-numbers#buying-on-telnyx).

**Release numbers.** An admin key can give a number back to its carrier, on
Twilio or Telnyx. Releasing is irreversible, so it is refused while the number
is bound (unbind it first) and needs `confirm` to repeat the number. It is
recorded in the audit log. Unbinding still never releases. On the platform's
shared carrier account, a project can release only the numbers it bought
through TurnCall; on its own Twilio or Telnyx account, any number. Deleting a
project releases none of its numbers: release them first, because once the
project is purged only the carrier's console can. See
[Release a number](/guides/phone-numbers#release-a-number).

**A compliance mapping.** One page maps redaction, retention, the audit log,
self-hosting, encrypted project credentials and signed webhooks to the GDPR
and then HIPAA, and lists what stays your responsibility. TurnCall holds no
certification, and the page says so. See [Compliance](/guides/compliance).
[Server Events](/guides/server-events#redaction) now describes what redaction
does to webhook payloads.

**SIP trunk guides.** TurnCall has no SIP endpoint of its own; a SIP trunk
reaches an agent through your Asterisk over ARI, or over a Twilio or Telnyx
elastic SIP trunk onto a number TurnCall routes. Each path has a guide with
the carrier's side and TurnCall's: [SIP trunk through
Asterisk](/guides/sip-asterisk) and [SIP trunk through Twilio or
Telnyx](/guides/sip-trunking).

**Audit log.** Every change made through the API to a project's agents,
credentials, phone numbers, API keys and settings is recorded: which API key
made it, what it did, and what changed, with secrets never recorded. Admin
keys read it with `GET /v1/audit-log`, and each change's response names its
entry in `X-TurnCall-Audit-Id`, which also reads back everything the request
changed (`?request_id=`). Entries are append-only and kept until the
operator's `AUDIT_LOG_RETENTION_DAYS`, which call retention does not touch.
See [Audit log](/guides/audit-log).

**Retention.** A project can choose how long its calls' recordings,
transcripts and events are kept, and an agent can override it. A janitor
deletes what has expired, including a Twilio copy of the recording it was told
about; the call record stays and says what was deleted.
`call.ended` states the retention that applies. Unset, everything is kept, as
before. See [Retention](/guides/retention).

**Redaction.** A project can have its callers' phone numbers, emails, card
numbers and more replaced in the transcript, the call's event log and every
webhook, before they are stored or sent. The agent still hears them during
the call. Detection runs locally, and nothing changes until an admin turns it
on. See [Redaction](/guides/redaction).

**Redaction in logs and traces.** A redacting project's log lines and
OpenTelemetry spans have its callers' phone numbers, emails, card numbers,
SSNs and IBANs replaced before they leave the server: the transcripts the
observers log, the text on the pipeline's spans, the numbers the webhooks
log. See [Logs and traces](/guides/redaction#logs-and-traces).

**Redaction of text conversations.** With redaction on, SMS, WhatsApp and Chat
API sessions read back redacted through the Chat API, and a session's stored
messages and numbers are rewritten redacted once it ends. The agent still
reads them while the session is live. A page of chat sessions or messages now
holds at most 500 (a larger `limit` is cut to 500). See
[Text conversations](/guides/redaction#text-conversations).

**A website demo server.** `turncall-demo` runs agents from a JSON file over
WebRTC with no database, Redis or project — the real voice pipeline behind a
"talk to an agent" button, in a container per visitor. See
[Website demo](/guides/website-demo).

**A TURN relay for WebRTC.** `WEBRTC_ICE_SERVERS` sets the ICE servers our side
of a browser call gathers with; public STUN stays the default. A server behind
NAT needs one, or the browser connects and hears nothing. See
[WebRTC](/guides/webrtc#behind-nat-a-turn-relay).

**Template variables on a WebRTC call.** `variables` in the connect request's
`requestData` fill the agent's `{{placeholders}}` for that call. With
`server_url`, call-init sees them as `call.variables`, and the request's value
wins a clash. See [WebRTC](/guides/webrtc#template-variables).

**Template variables in text conversations.** `POST /v1/chat` takes
`variables`, kept on the session and rendered into the agent's prompt as
`{{placeholders}}`. An SMS or WhatsApp text to a number routed to call-init now
asks your server once per conversation (`call.type` `inboundSms` /
`inboundWhatsAppMessage`) and runs the agent it names — stored or inline —
with its `variables` and `knowledge_context`. Before, such a number left texts
unanswered. See [SMS / Chat](/guides/sms-chat#template-variables) and
[Pre-Call Init](/guides/call-init#text-conversations-sms-whatsapp-text).

**An outbound call from a call-init number runs call-init.** A call placed
with `POST /v1/calls/outbound`, or by a campaign, from a number routed to your
server now asks it first (`call.type` `outboundPhoneCall`), before the phone
rings. Its `agent_id` or inline `agent` runs the call, its `variables` merge
under the dial's, and a call-init that fails leaves the dial's agent to run.
See [Pre-Call Init](/guides/call-init#outbound-calls).

**An inline agent brings its own knowledge bases.** Call-init's `agent` (and an
eval's `inline` target) names them in `knowledge_bases`, with a link's fields.
Before, an inline agent ran with none, silently. Each is resolved against the
call's project; one that is not there is skipped with a warning. See
[Knowledge Base](/guides/knowledge-base#inline-agents).

**Usage limits per project.** `PUT /v1/projects/{id}/limits` caps the
project's live calls, how many outbound calls each of its numbers starts per
second, and how many messages one text conversation sends per minute. They hold
across servers, and anything over a limit is refused as `rate_limited` —
inbound calls at the carrier before they are answered, with a `call.rejected`
webhook. The `LIMIT_*` environment variables set the platform default. See
[Limits](/guides/limits).

**Google Gemini as the agent's LLM.** `"llm": {"provider": "google"}` runs
Gemini (`gemini-3.6-flash` by default) on voice and text, tools included, on
the same `google` account Gemini Live uses. It also works as an `llm.failover`
entry. See [Providers](/guides/providers#llm-configuration).

**AssemblyAI speech-to-text.** `"stt": {"provider": "assemblyai"}` uses
Universal-Streaming — the English model by default, the multilingual one for an
agent whose `stt.language` is another language — with `stt.keyterms` passed as
its keyterms prompt. See [Providers](/guides/providers#stt-configuration).

**Helm chart.** The chart in
[turncall-charts](https://github.com/kobikis/turncall-charts) runs the API and both workers against your
own Postgres and Redis, runs migrations before each install and upgrade, and
sizes every pod's grace period so scaling down or rolling out lets live calls
finish. Optionally autoscales the API on live calls per pod, and runs the
builder beside TurnCall. See [Kubernetes](/guides/kubernetes).

**Deepgram Flux STT.** Set `stt.model` to `flux-general-en` (or
`flux-general-multi`) on the `deepgram` provider and Flux decides when the
caller has finished speaking — Smart Turn is not run for that agent. Each
turn's `metrics.turn` event now carries `turn_end_ms`, the time it took to call
the turn over. See [Deepgram Flux](/guides/agents#deepgram-flux).

**Backup STT and TTS providers.** `stt.failover` and `tts.failover` list backup
configs in order, like `llm.failover`. If the speech provider stops working
mid-call (a refused key, an unknown model or voice), the call moves to the next
one and carries on — the backup transcribes what the caller had just said, or
speaks the reply that was cut off. Recorded as `provider.failover` and in
`failovers` on `call.ended`. See [Failover](/guides/providers#failover).

**A deploy no longer drops live calls.** On `SIGTERM` the readiness probe fails
at once while liveness stays green, and the process keeps serving until its
live calls have ended and their `call.ended` webhooks have gone out. A new
`GET /metrics` exposes `turncall_active_calls` for autoscaling. See
[Graceful shutdown](/guides/graceful-shutdown) for the grace period to set.

**Pause, resume or cancel a campaign.** `POST /v1/campaigns/{id}/pause` stops
new dials without hanging up calls in progress; `/resume` picks up where it
stopped; `/cancel` ends it, marking undialled targets `cancelled` and
sending `campaign.cancelled`. A campaign worker that crashes mid-dial no longer
leaves targets stuck, and never dials a target twice to recover. See [Campaigns](/guides/campaigns#pause-resume-cancel).

**Campaigns — one agent calls a list.** `POST /v1/campaigns` with JSON
targets (a number, its own variables for the agent, and a timezone), and the
new `turncall-campaign-worker` process dials each one once, skipping your
suppression list and staying inside the project's live-call limit. Each
target's status is on `GET /v1/campaigns/{id}/targets`. See
[Campaigns](/guides/campaigns).

**Transfers and DTMF on Telnyx numbers.** `transfer_call` and
`POST /v1/calls/{id}/transfer` work on a Telnyx call as on Twilio, cold and
warm: the caller hears your `transfer_message`, then ringing; on a warm
transfer the operator hears the `briefing` before being connected; a
voicemail on the operator's line is reported as `transfer.answered`, and an
operator who doesn't answer gets the caller your `fallback_message`.
`send_dtmf` works too.

**Telnyx numbers answer inbound calls.** Bind a number with
`"carrier": "telnyx"` and TurnCall routes it to itself on your Telnyx account —
no Mission Control step; a number the account does not hold is refused. The
call runs the same agent as on Twilio, with
recording, ambience and voicemail detection unchanged. Webhooks are verified
with your Telnyx account's public key, and a call over your live-call limit is
refused busy, as on Twilio. See
[Telnyx numbers](/guides/phone-numbers#telnyx-numbers).

**Asterisk numbers.** A number on your own Asterisk PBX can now reach an agent
over ARI, with no cloud carrier in between: bind it with `carrier: "asterisk"`
and give the project its Asterisk as an `asterisk` credential. Hang-up, DTMF
and cold transfers go through ARI. See
[Asterisk numbers](/guides/phone-numbers#asterisk-numbers).

**Campaign calling windows.** `calling_window` sets the hours and days a
campaign may call, read in each target's own timezone — daylight saving
included. A target outside its window waits for the next opening. See
[Campaigns](/guides/campaigns#calling-windows).

**Campaign retries.** `retry_policy` redials a target whose call went
unanswered, was busy or reached voicemail — each with its own number of
attempts and spacing, inside the calling window. See
[Campaigns](/guides/campaigns#retries).

**Campaigns split between agents, and tell you when they start and finish.**
Give `agents` with weights instead of `agent_id` and each target is assigned an
agent by its number, the same way phone-number A/B routing does. Subscribers get
`campaign.started` and `campaign.completed`. See
[Campaigns](/guides/campaigns#a-b-test-agents).

**Campaigns pace themselves.** A campaign dials at your number's
`outbound_calls_per_second` — never past it, and never past `live_calls`, even
with several workers — and at one call a second when you set no rate. See
[How it paces](/guides/campaigns#how-it-paces).

**Outbound calls from Telnyx numbers.** `POST /v1/calls/outbound` — and so a
campaign — dials from a Telnyx number with the same request as from a Twilio
one, inside the same suppression list and limits. An unanswered call ends
`customer_did_not_answer`, as on Twilio.

**`openai_live` agents with tools work out of the box.** An agent with tools and
no `s2s.delegation` block now delegates to its own `llm` (`"mode": "client"`),
with your keys, running your webhook and MCP tools — `end_call`, `do_not_call`
and `transfer_call` included. See
[Delegation](/guides/s2s#delegation).

**`llm.failover` reaches an `openai_live` agent's own-`llm` delegate.** If the
delegate's provider fails, delegations move to the next backup, recorded as
`provider.failover` like on cascade. See [Delegation](/guides/s2s#delegation).

**`openai_live` agents configure their delegate with `s2s.delegation`.**
gpt-live-1 calls no tools itself — it hands them to a delegate. The new block
names an OpenAI-hosted Responses model with its reasoning effort, service tier,
own instructions and a timeout (default 30 seconds), and gpt-live-1 is told to
delegate from your tools' own descriptions, so no prompt rewrite is needed.
`s2s.extra.backend_model` keeps working. `handoff_to_agent` on `openai_live` is
now refused. See [Delegation](/guides/s2s#delegation).

**Project credentials — each project can run on its own provider accounts.**
`PUT /v1/credentials/{provider}` stores one key per provider account (one
Deepgram key for transcription and voice, one OpenAI key for every role),
encrypted and never returned. Every call, chat turn, post-call analysis,
knowledge-base upload and eval run uses the agent's own key, then the project's,
then the environment's — so the environment becomes a fallback rather than a
requirement. `GET /v1/providers` lists providers per role and whether each has a
platform key and a project key. New setting: `CREDENTIAL_ENCRYPTION_KEY`. See
[API keys](/guides/providers#api-keys).

**A phone number can bring its own Twilio account.** Bind it with
`twilio_account_sid` + `twilio_auth_token` and TurnCall looks the number up on
that account, stores the token encrypted, and uses that account for everything
the number does. See [Phone Numbers](/guides/phone-numbers#bring-your-own-twilio-account).

**Ambience: a room the agent sounds like it is in.** Upload a sound once
(`POST /v1/ambience-sounds`) and any agent in the project names it:
`"ambience": {"sound": "<id>", "volume": 0.3}`. It plays quietly under
everything the agent says, on Twilio, WebRTC and WhatsApp voice, S2S included.
Uploads are normalized for every transport, and a sound too low to survive a
phone line is flagged at upload. See [Ambience](/guides/ambience).

**Everything in the cluster with Helm.** The chart's `values-local.yaml`
runs TurnCall with its own Postgres (pgvector) and Redis and keeps files on a
volume — the docker compose stack on Docker Desktop, kind or minikube. The
chart fills `DATABASE_URL` and `REDIS_URL` and migrates before the API starts.
`publicBaseUrl` sets the public URL carriers call. For development.
See [Kubernetes](/guides/kubernetes#everything-in-the-cluster-development).

## Changed

**pipecat 1.13.** The speech framework TurnCall runs on moves to 1.13, with
these changes you may notice:

- An `openai_live` agent's delegations run one at a time, a later one waiting
  for the delegate to finish. A `delegation.completed` event reads `answered`
  only when the delegate said something to the caller, and its `duration_ms`
  includes the wait. When the delegate ends the call, everything it says after
  that is spoken before the hangup, not just the first thing.
- In evals, the tool calls an `openai_live` agent's delegate makes appear as
  `function_call` events. A scenario that expected none may change its verdict.
- Anthropic and Google models now run at their lowest reasoning setting when
  the agent sets none, for a faster first word.
- The voice activity detector is better at quiet voices and phone audio, and
  may report that the caller stopped speaking a little later.
- Fixes that come with it, among them: the agent's voice going silent for the
  rest of a call, a Telnyx call ended by one malformed message, the end of a
  turn cut mid-word, speech recognition that never failed over after its first
  connection failed, and Anthropic input tokens reported doubled.

**Evals off pipecat's deprecated eval transport.** The eval worker no longer
uses anything pipecat 1.13 deprecated for evals, so the move to pipecat 2.0
will not break it. Each run now serves pipecat's harness from a loopback
server of its own and builds the agent once the harness connects. Scenarios,
verdicts and the `evals-jev` extra's name are unchanged.

**A production WebRTC `server_url` may be a Kubernetes Service.**
`http://<name>.<namespace>.svc.cluster.local` is accepted beside HTTPS, so a
call-init server in the same cluster works; any other `http://` URL is
refused outside development. See [WebRTC](/guides/webrtc#dynamic-routing).

**A phone number's carrier is `carrier`.** Phone-number reads carry
`carrier`; `provider` keeps the same value and is still accepted on a write,
both deprecated, since "provider" names an STT, LLM or TTS backend everywhere
else. A number's carrier is fixed once bound. See
[Phone Numbers](/guides/phone-numbers).

**A call that fails says so, and why.** A provider that stops working mid-call
(a refused key, an unknown model) used to leave the call reading as
`customer_ended_call`. It now ends `failed` with an `ended_reason` of
`pipeline_error`, and an `error.raised` event says what broke. See
[When a call fails](/guides/post-call-analysis#when-a-call-fails).

**A missing provider key is caught before the call starts.** If no level holds
a key for a provider the agent uses, the call is refused up front, naming it
(`missing_keys`), instead of failing partway into the greeting. WebRTC answers
`500 pipeline_start_failed`. See [API keys](/guides/providers#when-a-key-is-missing-or-refused).

**`AWS_AGENT_CREDENTIALS_ENABLED` governs agent config only.** Static AWS keys
are still refused inside an agent's `aws` block when it is off, but an `aws`
project credential is accepted — it is encrypted and outside agent config.

**A carrier's media stream must prove it belongs to the call (security).** A
call id is not a secret, and any WebSocket that named one could open a second
pipeline on a live call — hearing the caller's agent and driving its tools.
TurnCall now gives each call a media token that only its carrier receives, in
the call's own stream setup, and refuses a stream without it, one on another
carrier's route, and a second stream for the same call. Nothing changes for a
number bound through the API. The token is keyed by `API_KEY_HASH_SECRET`:
rotating it refuses the stream of a call answered under the old value that has
not started streaming yet.

**An inline agent's config is never shown (security).** Call-init's inline
`agent` can carry credentials — MCP headers, an `llm.api_key`, AWS keys — and
the call read and `call.ended` returned it in `metadata`. Both leave it out
now, and a text session's never appears in a session read.
`POST /v1/calls/outbound` refuses a `metadata.dynamic_config` with a 422: it ran
as the call's agent, around every check an agent create makes. See
[Returning an inline agent](/guides/call-init#returning-an-inline-agent).

**ICE trickle needs your API key (security).** `PATCH /v1/webrtc/connect`
took no key, so anyone who learned a live call's `pc_id` could add ICE
candidates to its connection. It now needs the same admin or developer key as
the `POST`, for the call's project: no key is a `401`, another project's or an
unknown `pc_id` a `404`. pipecat's browser transport sends the `POST`'s
headers on every `PATCH`, so a client that put `Authorization` there needs no
change; a proxy that forwards the `PATCH` must add the key. See
[ICE Trickle](/guides/webrtc#ice-trickle).

**Ambience is in the call recording.** The agent's channel carries the room, as
the caller heard it. The docs said it was left out, but it has always been in
the recording. See [Ambience](/guides/ambience).

## Fixed

**A speech-to-speech call starts as soon as its model is connected.** An
OpenAI Realtime, Gemini Live or Nova Sonic call used to wait a fixed two seconds
before the agent could speak or hear. Measured on the same machine, an OpenAI
Realtime agent now greets about 1.2 seconds sooner (p50 2.9 → 1.7 s from the
call's start). Gemini Live and Nova Sonic agents hear the caller from about
0.5 s and at once, where they used to drop the first two seconds of what the
caller said. `openai_live` agents already started at once and are unchanged.

**Gemini Live and Nova Sonic agents speak first.** They used to wait for the
caller to say something before saying anything. They now open the call with
the agent's `first_message`, or a greeting when it has none, as OpenAI Realtime
and `openai_live` agents do. Measured from the call's start, the first audio
leaves the model at about 1.2 s on Gemini Live and 1.6 s on Nova Sonic (p50).
They still hear the caller as soon as before.

**`call.ended` is prompt when the caller hangs up while the call connects.** It
used to arrive about 15 seconds late, waiting for a recording that was never
started. It now arrives at once, with `recording_status: "none"`.

**`call.ended` arrives once, as `completed`.** When the agent hung up just as
the carrier reported the call over, a subscriber could get `call.ended` twice,
or once with `status: "in_progress"`. It now arrives once.

**`call.ended` carries the call's last lines.** When the caller hung up right
after speaking, or the call was ended through the API, `call.ended` and its
analysis could miss the last thing said. They now wait for the call's
transcript to be complete.

**Telnyx errors reach the logs.** A log line carrying a Telnyx error, or a few
of TurnCall's own, was dropped with a loguru "Logging error" instead of being
written. It is written now.

**Bind finds your Twilio number exactly.** Binding a number on your own Twilio
account could pick a different number on that account whose digits contain
the one you named. It now takes only the exact number.

**Telnyx not answering a bind is a `502`.** It was a `500`.

**A Twilio account that rejects its credentials is a `422` on bind.** Binding
a number on your own Twilio account with a wrong Auth Token answered `500`; it
now answers the documented `422`.

**Numbers in event payloads are redacted.** With redaction on, a phone or
card number a tool's arguments or a call's `metadata` carried as a JSON number
(`{"phone": 4155550132}`) went out raw in `tool.result` and `call.ended`
webhooks and on the event log. It is now analysed as the digits it is
written with, as tool invocations already were. See
[Redaction](/guides/redaction#what-is-redacted).

**A WebRTC call's greeting is no longer lost.** The agent's first message was
spoken as the pipeline started, and audio written before the browser's
connection is up is dropped — so a greeting ready before ICE and DTLS finished
(a fast voice, a slow network, a TURN relay) played to nobody. It now waits
for the connection.

**`/health` reports a reachable database as healthy.** It read
`"database": "unhealthy"` on every deployment. `/ready` was unaffected.

**A knowledge base in `tool` mode works in text conversations.** The Chat API,
SMS and WhatsApp text skipped tool mode, so the model was never offered
`query_knowledge` and a document read that way was invisible outside voice
calls — the builder's Test Chat included. Text turns now offer it, run the
same search a voice call does, and record each call as a tool invocation on
the session.

**`auto` knowledge retrieval works on voice calls again.** No voice call in
`auto` mode retrieved a passage: the retrieval step listened for frames the
call no longer sends. Each caller turn now gets that turn's passages, placed
right before it, and the previous turn's are taken out so the prompt does not
grow with every turn.

**A voice call's `query_knowledge` searches are recorded.** They now appear in
`tool_invocations` and as `tool.result` events, like every other tool call.
Before, a search left no record, and an agent that looked something up read as
one that never did.

**An agent with a `tool`-mode knowledge base searches before saying no.** The
model is now told to look something up with `query_knowledge` before telling
the customer it doesn't have it. Before, an agent sure of the answer from its
name could deny something its documents list, on voice and text alike.

**An eval mocks `query_knowledge` like any other tool.** A knowledge search
in an eval ran against the real knowledge base whatever the tool policy, and
never appeared in the iteration's `tool_calls`. It now follows `tool_policy`:
a `tool_mocks` entry for `query_knowledge` answers it, and under `mock_only`
(the default) an unmocked search is refused and the iteration is `errored`
naming it. A scenario for an agent with a `tool`-mode knowledge base needs a
mock for it, or `tool_policy: live` to search for real.

**A failed knowledge search no longer tells the model why.** The model is told
only that the search failed. The exception's text, which it could repeat to the
customer, goes to the log.

**A WebRTC renegotiation no longer starts a second call.** A browser client
that re-sends its offer for a connection it already has (the pipecat client
does when it restarts ICE) got a new call row stuck at `initiated`, a second
call-init request, a live-call slot held until it expired, and that stray
call's id in the answer. The offer now renegotiates the running call and
answers with its `call_id`; a `pc_id` belonging to another project's call is a
`404`.

**call-init is told the call's real id.** On an inbound phone call, a WhatsApp
voice call and a WebRTC call, `call.id` was a stand-in that nothing after it
carried, so a server could not match the call-init it answered to the call's
events. It is now the id the call is created with, as it already was on an
outbound call.

**A handoff keeps the call's variables and call-init context.** After
`handoff_to_agent`, or a handoff through the API, the new agent read the
`{{placeholders}}` in its prompt literally and lost call-init's
`knowledge_context`. It now gets both, as the first agent did.

**`smart_turn_detection: false` turns Smart Turn off.** pipecat's default turn
end is Smart Turn, so an agent with it off still ran the model and waited on it
after `silence_timeout_ms` — a slower turn than the setting promised. The turn
now ends on VAD's silence alone.

**A call could find its own record missing.** An API request's writes were
committed after its response was sent, so a carrier fast enough to open the
media stream the moment it read the answer could reach a call that did not
exist yet, and hear silence. Writes are committed before the response now.

**A handoff through the API switches the live call.** `POST /v1/calls/{call_id}/handoff`
moved the call's record to the new agent while the caller kept talking to the
previous one. The call now switches itself — the new agent's prompt and tools —
and the response lists what it applied. It answers like `/messages`: **409**
(`call_not_live`), **504** (`call_did_not_acknowledge`), a 409 with the reason
when the call refuses (an `openai_live` agent, as for the `handoff_to_agent`
tool), and a **404** for an agent outside your project.

**Messages sent to a live call reach its agent.** `POST /v1/calls/{call_id}/messages`
answered 200 while the agent never saw the message. It is now added to the
agent's context for its next turn, and the response says what the call did: 200
once the call has applied it, **409** (`call_not_live`) when the call is not
running, **504** (`call_did_not_acknowledge`) when it does not confirm within
two seconds. Speech-to-speech calls refuse it with a 409, since their model
reads nothing added to its context after the call starts.

**An `openai_live` agent checks in on a quiet caller.** The idle check-in never
reached gpt-live-1, so a caller who went quiet heard silence until the call's
maximum duration. gpt-live-1 now asks whether they are still there, and a second
silence ends the call as `customer_silent`. A silence while the agent's delegate
is still working does not count.

**Ambience turned off the idle check-in on `openai_live`.** With ambience on, the
call never registered the agent as done speaking, so a quiet caller was never
asked whether they were still there. Video avatars under ambience had the same
problem.

**An `openai_live` agent opens the call.** gpt-live-1 waits for speech, so an
agent with no `first_message` said nothing until the caller did, and one with a
`first_message` could stay silent too. The session now starts with an explicit
request to speak first: the `first_message`, or a greeting when there is none.
gpt-live-1 delivers it in its own words, usually verbatim.

**An eval that failed because a provider refused the agent now says so.** The
iteration's failures lead with the provider's error (for example Bedrock's
"Model use case details have not been submitted") instead of only "no response
text yet".

**A call that could not start went silent.** WebRTC answered the offer anyway
and connected the browser to nothing, and no `call.ended` was sent. It now
returns an error and sends `call.ended` without waiting for a recording that
cannot exist.

**An eval run whose project keys could not be read used the platform's keys.**
It is now `errored`, naming why.

**An OpenAI agent's `llm.api_key` was ignored.** It now wins over the platform
key, as it already did for Anthropic, OpenRouter and custom endpoints.

**Deleting a document or a knowledge base now deletes its files.** Before, the
rows went and the uploaded files stayed in storage forever. Re-uploading a
filename to one knowledge base also no longer overwrites the first document's
file. Deleting a project now also removes recordings stored through Twilio's
recording callback.

## Security

**Secrets are encrypted at rest.** Webhook subscriptions' signing secrets, a
number's call-init `server_url_secret`, and an agent config's `llm.api_key`,
static AWS keys, `server_url.secret`, tool `webhook_secret`s and MCP `headers`
and `env` values were stored in plaintext, so a database dump or backup gave
them away. They are now encrypted under `CREDENTIAL_ENCRYPTION_KEY`, on the
agent and in inline configs on calls, SMS sessions and eval targets alike.
Signatures, call-init, tools and MCP servers work as before. Without the key,
saving one is a `503` (`credential_key_unavailable`) rather than a plaintext
write. A dump together with the key still reads them, and call data is stored
as it was. See [Compliance](/guides/compliance).

**Outbound URLs must be `https://` outside development.** Webhook
subscriptions, a number's call-init `server_url`, and an agent's
`server_url.url`, tool `webhook_url`s and MCP server `url`s took `http://` in
every environment, so call data could cross the network in cleartext. Plain
http is now accepted only when `TURNCALL_ENV` is `development`, or anywhere
with `ALLOW_PLAIN_HTTP_URLS=true`; elsewhere, staging included, it is a `422`.
In-cluster `*.svc` hosts are allowed. Loopback and private addresses are not.
Inline configs are not refused: an inline agent from a call-init answer, an
eval run's `inline` target, a `turncall-demo` agents file. Their plain-http
deliveries are logged, as are those to URLs stored before the upgrade, which
startup also names. See
[Compliance](/guides/compliance).

## Added

**Evals: automated behavioural testing for agents.** State what an agent must do
and have TurnCall check it on every change. Scenarios are **scripted** (a fixed
conversation with per-turn expectations) or **simulations** (a persona and a
goal, improvised by an LLM and judged on the outcome), run in text or audio
modality against the agent's real pipeline. A dedicated worker executes them,
never the API process. See [Evals](/guides/evals).

**Tool mocking, failing closed.** A scenario carries `tool_mocks` and a
`tool_policy`; under the default `mock_only` a tool call with no mock is refused
and the run is errored naming it, so pointing a scenario at a real agent cannot
book a real appointment ten times.

**`turncall eval run` exits non-zero when your agent regressed**, so a pull
request can be gated on behaviour. A failure is `1`, an error `2`, a cancellation
`3`, a batch still running when the command stopped waiting `4`, a usage mistake
`64` — distinct because "your agent regressed" and "we could not check" want
different alerts, and a judge outage must never read as a regression.

**`eval.run.started` / `eval.run.completed` webhooks.** The completed event is
comprehensive: status, counts, every iteration's transcript and failures, and
the configuration snapshots. The envelope gains a nullable `eval_run_id` beside
`call_id` and `session_id`; existing subscribers are unaffected.

**Choose the model that judges an eval.** A scenario names
`judge: {provider, model, temperature}` and `simulator: {...}`; `provider` is a
closed set — `ollama`, `openai`, `anthropic`, `jev` — mapping to factories
TurnCall ships, because pipecat's own escape hatch is a dotted import path and that is
remote code execution from a request body. `EVAL_JUDGE_PROVIDER` / `_MODEL` /
`_TEMPERATURE` (and the `EVAL_SIMULATOR_*` trio) set one for the whole platform;
the scenario's block wins, taken whole. A `judge` on a **run** request is
refused, because a run is what it was queued as. Sending `"judge": null` on an
update returns a scenario to the default. See
[Choosing the judge](/guides/evals#choosing-the-judge).

**`jev` as a judge** — TypeSafe's classifier, a few hundred milliseconds per
verdict with a *calibrated* probability rather than a model's opinion of its own
certainty. Judge-only, and structurally so: the provider allowlist is split by
role, because a simulator is linked into a live pipeline to speak and a
classifier has nothing to link, so `simulator: {"provider": "jev"}` is refused
naming the role. Needs `TYPESAFE_API_KEY` and the `evals-jev` extra — neither
checked at scenario create, because both belong to a deployment and a stored
scenario outlives the one it was written against, so the **run** fails naming
which is missing.

**TurnCall decides who writes the reason.** Since pipecat 1.12 the verdict comes
from a classifier and a second model — the explainer — writes the prose behind
every `no`. For a classifier-only judge pipecat falls back to its own default LLM
service, a local Ollama, so a judge pointed at a hosted vendor would silently
acquire a dependency on a service nobody provisioned and report it as an
unreachable connection mid-run. The explainer is compiled from the platform's
configured judge instead, and where the platform configured none, reasons are
turned **off** explicitly. LLM-backed judges are left exactly alone.
`harness_config` records `explainer_used`, `explainer_provider` and
`explainer_model`.

**A confidence beside every verdict a judge produced** — a scripted expectation
and its failures, a simulation's goal verdict, and each per-turn verdict of a
judged metric. `null` is not zero: zero means the judge was certain of the
opposite. There is deliberately no aggregate. Pipecat 1.12 carries a confidence
and then drops it building the result objects TurnCall reads, so the field is
`null` on runs today and starts reporting on the bump that threads it through.

**A run carries its own `warnings`** instead of the worker's log — a mock keyed to
a tool the run can never call, an agent whose real tools are allowed to fire, a
scenario in which nothing can fail, a judge that changed since the last verdict,
a worker older than the code it runs. They ride on the run, the batch summary,
`eval.run.completed` and `turncall eval show`, because the person reading a green
verdict is rarely the one who wrote the scenario.

**A light read for a run, and paged eval lists.** `GET /v1/eval-runs/{id}?view=summary`
answers "is it done yet" without every iteration's transcript and all three
snapshots, and both eval lists page in the same `paginated` envelope the rest of
the API uses. `eval.run.completed` stays comprehensive: that argument is about a
subscriber who gets one event, not an endpoint on a timer.

**`tts.pronunciations`** — a flat word → IPA map, the outbound mirror of
`stt.keyterms`. One spelling, each provider's own markup generated from it:
Cartesia inline phonemes, ElevenLabs SSML `<phoneme>`, Deepgram's inline object;
OpenAI has no pronunciation surface. Validation is TurnCall's own, because
pipecat's IPA helpers normalize and tokenize but never reject — so `met-FOR-min`
would be accepted, inserted into the markup and change nothing audible, and is a
`422` naming the word. On a voice that cannot read the markup the markup is
**withheld**: a `<phoneme>` tag reaching a service that is not parsing SSML is
read out loud, measured at 3.5–4.3× the audio, which is worse than the
mispronunciation. See [Pronunciations](/guides/providers#pronunciations).

**`warnings` on an agent read.** Two things an author needs told that cannot be
refusals: a "pronunciation" equal to its own spelling (`{"Metformin": "metformin"}`
— every character is legal IPA, so the validator cannot see it, and it reaches
the voice as real markup), and a voice that will not read the markup, which was
known at pipeline build and said only to a server log, mid-call, about a config
written days earlier. Derived on every read and never stored, so an agent whose
model moved out from under its pronunciations starts saying so without being
edited.

**A verdict says which judge decided it.** `harness_config` gains
`judge_provider` and `judge_temperature` beside the model, service and factory
it already recorded — and a run whose judge differs from the same scenario's
last verdict carries a `judge_changed` warning naming both, so a scenario that
turns red can be told apart from a judge that moved underneath it.

**A run records the code that executed it** — `worker_version`,
`worker_started_at`, and `worker_stale` when the worker's source is newer than
the process running it. A worker left running while the code moves under it
produces results that look ordinary and silently lack whatever shipped since.

**Derive a scenario from a real conversation** — `POST
/v1/eval-scenarios/from-call` turns a finished call into a draft, and
`POST /v1/eval-scenarios/from-session` does the same for an SMS, chat or
WhatsApp conversation. Each tool mock is seeded with what that tool actually
returned.

**`POST /v1/webrtc/connect` returns the call id** beside `sdp` and `type`. A
browser that had just held a conversation could not say which call it was, so it
could not fetch the transcript, link the recording, or convert it. Additive — a
client reading only `sdp`/`type` sees no change.

**Tool calling on SMS, chat and WhatsApp text.** Text conversations could not
call tools at all — an agent that books meetings on a phone call would claim it
had booked one over SMS. Works on every provider family: OpenAI-compatible,
Anthropic and Bedrock Converse each have their own dialect. Calls within a round
run concurrently, and the loop re-asks with tools withheld after five rounds so a
reply always goes out. Built-ins stay voice-only.

**Text tool calls are recorded.** `GET /v1/chat/sessions/{id}/tool-invocations`.
`output_json` and `latency_ms` are populated on both voice and text, and a tool
returning `{"error": ...}` is recorded as failed rather than succeeded.

**`execution_mode: "async"`** lets a slow tool outlive an interruption instead of
being cancelled by it. Voice only.

**`max_call_duration_seconds`** now caps a call, with its own `ended_reason` of
`max_duration_reached`. **`interruption_enabled: false`** turns off barge-in on
cascade. **`silence_timeout_ms`** sets the VAD stop window. All three were
documented and did nothing.

**New limits you can set:** `MCP_MAX_TOOLS_TOTAL`, `MCP_CONNECT_TIMEOUT_SECONDS`
and `TOOL_MAX_RESPONSE_BYTES`.

**`stt.keyterms`** — one list of vocabulary hints (product names, SKUs,
surnames), mapped to whatever the chosen provider calls it: `keyterm` on
Cartesia, `keywords` on OpenAI, `keyterms` on ElevenLabs, and on Deepgram
whichever spelling the model takes. Deepgram 400s on the wrong one rather than
ignoring it, so hand-writing `extra: {"keyterm": ...}` on a Nova-2 agent killed
the call at connect; `keyterms` picks correctly and takes precedence over
`extra`.

**`user_idle_timeout_ms`** (default `10000`, `0` disables) ends a call the
caller has walked away from. After the agent stops speaking, that much silence
prompts `idle_message` ("Are you still there?"); a second consecutive silence
hangs up with a new `ended_reason` of **`customer_silent`**. Speaking resets the
count. Cascade speaks the line through TTS; S2S asks the model to check in and
words it itself.

## Changed

**Pipecat 1.12**, up from 1.9 via 1.10 and 1.11, and the `openai` 3 SDK. See
`adr/0019`. Voicemail detection is now one processor over an explicit
`LLMClassifier`, `nltk` is replaced by `sentencex`, and the `ollama` judge is an
`LLMClassifier` with a 60s budget: 1.12 judges a simulation one bot turn per call
and fires those calls together against a 10s default, and a local Ollama
serializes them — measured at 18s each for four concurrent against 4.5–5.8s
alone, so every turn timed out and the run reported `judge call failed`, which
from outside is indistinguishable from an agent regression.

**An empty user turn is handled rather than dropped**, and on by default. A turn
VAD opened and closed with no transcript — a cough, a door, an unrecognized word
— gets a single LLM run if it *interrupted* the agent, so the agent asks the
caller to repeat instead of stopping dead mid-sentence. One arriving while the
agent was already waiting is left alone: replying to a passing truck is
intrusive, and the idle timeout already covers a caller who has genuinely gone
quiet.

<Warning>
  **Breaking:** `mcp` 1.x is no longer supported. Pipecat 1.12's `mcp` extra
  requires `>=2.1.1`, so the dual-spelling reads that briefly supported both
  lines are gone — under that pin they could never match.

<Warning>
  **Breaking:** `/v1/test-suites` and `/v1/test-runs` are removed. Six endpoints

**`stt.model` and `llm.model` now mean "the provider's own default" when

on Anthropic. An explicit value is still passed through untouched, so a wrong

**MCP tool-name precedence follows your configured server order** rather than
whichever server answered the handshake first.

## Fixed

**The caller sat in dead air, 2.4–5.7s per turn.** VAD and Smart Turn were charged
one after the other rather than together — Smart Turn's silence counter cannot
start until VAD has waited out its own window, which at the 800ms default put
end-of-turn 1.8s after the caller stopped talking before the LLM was even called.
With Smart Turn on, the model decides the turn and VAD uses pipecat's 0.2s.

**Every eval run scored `errored` — no eval feature had ever reported a verdict.**
Pipecat's harness is an RTVI client and the server half is a processor in the
bot's pipeline plus an observer on the task; TurnCall built neither, so every
iteration died at the `bot-ready` handshake. Because `errored` counts toward no
rate, the outage read as "no signal".

**A handoff could not survive the caller talking over it.** `handoff_to_agent`
queues the target's prompt and tool schema as frames, and pipecat drains
interruptible frames on barge-in — so a caller saying "okay, thanks" mid-handoff
left the model running the previous agent's prompt, advertising the previous
agent's tools, over a context already wiped. Nothing raised and nothing was
logged. The switch is also atomic against cancellation now: an interruption
cancels in-flight sync tool calls, and a DB round-trip after the commit left the
call record handed off while the live pipeline kept the previous agent.

**`tts.pronunciations` could never work on ElevenLabs.** Pipecat reads SSML
`<phoneme>` tags only with a phoneme-capable model *and* `enable_ssml_parsing`, a
constructor argument no `tts.extra` could reach. TurnCall passes it for exactly
the agents that have pronunciations and such a model — never for everyone, since
SSML parsing changes how all of that agent's text is read.

**Cancelling a running eval run now stops it, and stays cancelled.** `DELETE` set
the column and nothing else: every remaining iteration ran and was paid for, and
the finisher then wrote `passed` over `cancelled` and announced
`eval.run.completed` for a conversation the user had asked to stop.

**A hung eval iteration is bounded**, and the janitor's cutoff is derived from the
run's iterations rather than a flat 900s. Both were the same false alarm from
opposite ends: an unbounded harness call held a worker slot for the life of the
process, and a flat sweep reclaimed healthy multi-iteration runs mid-flight —
which the CLI reported as a regression.

**A tag's fan-out is capped.** One POST with a popular tag and `iterations: 50`
queued `scenarios × iterations` full conversations, so a project with 200
scenarios on `pre-publish` was 10,000 conversations away from one HTTP call.
`EVAL_MAX_SCENARIOS_PER_REQUEST` (50) refuses it naming the count, never
truncating.

**The CLI's deadline fits the batch**, and a batch that outran it exits **4**, not
2. The default was a per-run budget used as a whole-batch one, so ten scenarios
behind a four-slot worker made the command give up on a healthy suite and report
an outage. "We stopped waiting" and "nobody could tell" are now different codes,
because they have different remedies.

**A scenario that cannot fail is warned about.** Validation checks shape, not
strength, so a scenario whose every expectation is a content-free event parses,
stores, runs and reports `passed` forever against an agent whose LLM returns
nothing — after a provider 404 pipecat still emits an empty `llm_response`. The
create/update response and the run both carry `scenario_cannot_fail`, and such a
run scores **`failed`**, never `errored`.

**The eval worker's readiness probe stopped looking like a failure.** Every
iteration logged `opening handshake failed` with a traceback and nothing was
wrong. The cost was not the noise: a probe succeeding and a bot that could not be
reached produced the same traceback.

**A sentence the STT split in two became two scenario turns** in `from-call`, and
audio evals work in Docker — pipecat's TTS cache default lives under `$HOME`,
which a container loses on recreate, so `EVAL_TTS_CACHE_DIR` exists and is
mounted.

**MCP servers now connect on WebRTC and WhatsApp voice**, and S2S advertises the
tools it was already holding sessions for. A tool name claimed by two servers no
longer makes the request invalid, and the tool that runs is the one the model was
shown. `handoff_to_agent` now swaps tools with the prompt.

**An inline agent from call-init** crashed Twilio calls, and on every transport
skipped post-call processing — which is what dispatches `call.ended`, so such a
call completed and told nobody.

**Tool results are capped** before they enter the context, for webhook tools as
well as MCP.

**A default `google` S2S agent sent OpenAI's model to Gemini.** `s2s.model` and
`s2s.voice` default to OpenAI Realtime's values whatever the provider, so an
agent naming neither reached Gemini holding `gpt-realtime-2.1` and `alloy`.
Gemini closed the socket with a 1008 and the call died at connect. Both
sentinels are now swapped for Gemini's own (`gemini-3.8-live`, `Charon`), the
way the `aws` and `openai_live` paths already did.

**The model reported in `call.ended` is the one that actually ran** — post-call
analysis resolved its own default separately from the pipeline, so the two could
disagree.

## Security

**An agent's secrets leaked through an eval run.** The config masker guarded one
exit — the agent response builder — and the eval feature added two more paths
carrying the same config: `GET /v1/eval-runs/{id}`, where a viewer key read every
credential in the clear, and `eval.run.completed`, which POSTed them to a webhook
subscriber. An inline target leaked the same way. The masker now lives where no
exit can miss it, and a run's stored `resolved_config` is masked on the way in.

**A judge or simulator cannot name a `factory`.** Pipecat's escape hatch is a
dotted path handed to `importlib.import_module` — fine for a file on disk, remote
code execution from a request body. One naming a factory anywhere pipecat reads it
is refused at the API boundary, and `api_key` is not a field.

**The BYOM/MCP URL allowlist could be talked past.** `*` in an `fnmatch` pattern
spans `/`, so `https://*.trusted.com/*` also accepted
`https://evil.com/x.trusted.com/y`. A pattern naming a host must now match the
URL's host on its own. MCP urls go through the gate too — they had none.

## AWS Bedrock and Amazon Nova Sonic

**New LLM provider: `bedrock`** — run Anthropic, Meta, Mistral or Amazon foundation models through AWS, on voice and on SMS/chat. Model ids pass through verbatim, so direct ids, cross-region inference profiles (`us.`-prefixed) and provisioned-throughput ARNs all work. `llm.extra` forwards to Bedrock's `additionalModelRequestFields`, which is how Anthropic extended thinking is reached.

**New S2S provider: `aws`** — Amazon Nova Sonic 2 (`amazon.nova-2-sonic-v1:0`), with `voice` defaulting to `matthew` and `s2s.extra.endpointing_sensitivity` (`LOW`/`MEDIUM`/`HIGH`) tuning how quickly it decides the caller stopped speaking.

**New `aws` agent config block** — one per agent, shared by both providers, so an agent's LLM and voice leg always authenticate as the same principal:

```json
"llm": {"provider": "bedrock", "model": "us.anthropic.claude-haiku-4-5-20251001-v1:0"},
"aws": {"region": "us-west-2", "role_arn": "arn:aws:iam::123456789012:role/turncall"}
```

Credentials are resolved by the server from an assumed `role_arn`, static keys, a named profile, or the ambient chain (env vars, SSO cache, EC2 instance profile, ECS task role, EKS IRSA). Nova Sonic sessions roll over roughly every 6 minutes and credentials are re-resolved each time, so calls outliving a temporary credential keep working.

**New setting: `AWS_AGENT_CREDENTIALS_ENABLED`** (default `false`) — per-agent *static* AWS keys persist in the agent config, which is not encrypted at rest, so agents supplying them are rejected at create unless this is enabled. `role_arn` needs no flag and stores no durable secret. `AWS_REGION` now also sets the default Bedrock region; set `aws.region` per agent, since model availability rarely matches where your S3 bucket lives.

See [Providers](/guides/providers#aws-bedrock), [Speech-to-Speech](/guides/s2s#amazon-nova-sonic), `examples/bedrock/`, and `adr/0016`.

## The system prompt moved onto the model, not the conversation

**Internal change, no config or API difference.** An agent's `system_prompt` — with guardrails and any prompt-mode knowledge preamble — is now set on the LLM service itself rather than inserted as the first message of the conversation. Pipecat deprecated the message form in 1.9 and stops honouring it in 2.0.

Two things follow. The conversation context now begins empty, so a transcript no longer carries the instructions as a phantom first turn. And `handoff_to_agent` switches agents by updating the model's instruction instead of rewriting that message — which had to change at the same time, because the instruction is prepended to the context, so doing both would have sent the previous agent's prompt alongside the new one.


## STT: provider passthrough

**`stt.extra` now reaches the provider.** The field has existed since the beginning and was silently ignored — the API accepted it, stored it, and dropped it. Keys naming a setting TurnCall already manages (`model`, `language`, and Deepgram's `punctuate` / `smart_format` / `interim_results`) are ignored rather than applied, so `extra` cannot quietly override your configuration.

On Deepgram it unlocks the rest of the transcription surface: `profanity_filter`, `diarize`, `redact`, `keyterm`, `version`, `utterance_end_ms`.

```json
"stt": {"provider": "deepgram", "extra": {"profanity_filter": true, "diarize": true}}
```

## Voice pipeline upgraded to Pipecat 1.9

**Upgraded from 1.8.1.** No config or agent changes required.

**Provider defaults refreshed** — these apply only to agents that do *not* set the value explicitly. Pin it in your agent config to keep the previous behaviour:

| Role | Setting | Was | Now |
|---|---|---|---|
| OpenAI STT | `stt.model` | `gpt-4o-transcribe` | `gpt-transcribe` |
| Deepgram STT | profanity filter | on | off |
| HeyGen avatar | video encoding | VP8 | H264 |

OpenAI shuts down `gpt-4o-transcribe` on 2027-02-26 and `gpt-transcribe` replaces it. LiveAvatar has deprecated VP8.

**Deepgram transcripts are no longer profanity-filtered.** Deepgram's filter rewrites the words it matches rather than tagging them, so one false positive silently altered a transcript you store, analyse, and receive in the `call.ended` payload. Transcripts now carry what the caller actually said. Set `stt.extra.profanity_filter: true` on an agent to turn the filter back on.

**OpenAI STT no longer clips the last word.** Segment-based STT now hears 0.5s of trailing silence before transcribing, so the final word of an utterance is transcribed instead of dropped or garbled. The padding is sent to the provider, so it counts toward your STT usage.

**Assistant transcripts no longer contain text the model never wrote.** A word-timing event that matched nothing left to speak was previously added to the conversation as spoken text. Nothing is lost — the text it should have covered is carried by the word that puts the sentence back in step.

**Fixed: ending a call during voicemail detection.** While the voicemail classifier's gate was closed, the frame that ends a call could be dropped instead of reaching the pipeline, leaving the caller on the line until the idle timeout. An agent calling `end_call` in that window now ends the call.

## TTS: speed, provider passthrough, and a newer Cartesia default

**`tts.speed` now works on every provider.** It was read only for Cartesia, so setting it on the default Deepgram voice did nothing. Deepgram (0.7–1.5), OpenAI and ElevenLabs all honour it now. Leaving it at `1.0` sends nothing, exactly as before.

**`tts.extra` now reaches the provider.** Previously only Cartesia's `language` and `emotion` were read and every other key was dropped. Keys naming a setting TurnCall already manages — `voice`, `model`, `speed` — are ignored rather than applied, so `extra` cannot quietly override your configured voice; set `tts.voice` for that.

**Cartesia's default model is now `sonic-3.6`**, matching Cartesia's current Sonic release. It applies only to agents that leave `tts.model` empty; pin `"sonic-3.5"` to stay on the previous one.

**Fixed: a Deepgram voice was being sent to other providers.** `tts.model` and `tts.voice` both default to `aura-2-helena-en` — a Deepgram Aura voice — whatever provider you set. An agent that chose Cartesia, OpenAI or ElevenLabs without also naming a model and voice sent that Aura name to the wrong provider. Each provider now falls back to its own default: `tts-1`/`alloy` for OpenAI, `eleven_flash_v2_5`/`Rachel` for ElevenLabs, `sonic-3.6` for Cartesia. Cartesia voice ids are account-specific, so an unset Cartesia voice now logs a warning naming the setting rather than sending something wrong.

## Knowledge retrieval is guidance, not a system prompt

**Chunks retrieved in `auto` mode are now attached as `developer` rather than a second `system` message.** They are guidance for the turn, not the agent's instructions, and a `system` message mid-conversation was already being downgraded to `user` by every provider except OpenAI — so this is no worse anywhere and correct on OpenAI. Your agent's own `system_prompt` is unaffected.

## New S2S provider: OpenAI GPT-Live-1

**`s2s.provider: "openai_live"`** runs OpenAI's `gpt-live-1`, [announced on 10 September 2026](https://openai.com/index/introducing-gpt-live-1-in-the-api/). It is **full duplex** — it listens and speaks at once, and decides for itself when to answer and when to stop on being talked over — where the Realtime API is turn-based. OpenAI reports a 30-point gain on Full Duplex Bench over `gpt-realtime-2.1`, and calls out telephony as a target.

```json
"pipeline_mode": "s2s",
"s2s": {"provider": "openai_live", "voice": "alloy"}
```

**Reasoning and tool calls can be delegated** to a backend text model while the conversation continues. Set `s2s.extra.backend_model` and OpenAI hosts it; the function calls it makes run against your agent's own tools. Left unset, the live model answers alone.

Two differences from `openai`: `s2s.temperature` is supported here (Realtime GA rejects it), and `s2s.turn_detection` must stay `server_vad` — client-side VAD would fight a model doing its own turn-taking, so `pipecat_vad` is rejected at config time.


</Update>

**Richer webhook payloads** — The `call.ended` webhook now includes call metadata (from/to number, direction, duration), the full transcript, and the recording URL. All call events are dispatched to webhook subscribers.

**Call recording storage** — Twilio call recordings are now automatically downloaded and stored locally or in S3.

**Pipecat 1.0 migration** — The underlying voice pipeline has been upgraded to Pipecat 1.0, improving stability and enabling new provider integrations.

**Renamed "assistant" to "agent"** — All API endpoints and documentation now use "agent" consistently. The `/v1/assistants` endpoints have been replaced by `/v1/agents`.

## Bug fixes


**Duplicate `call.started` events** — Fixed an issue where `call.started` was fired twice per call.

**Transcript sequencing** — Transcript events now use database sequence numbers, preventing ordering collisions in high-throughput calls.

**Webhook payload format** — Fixed the webhook event key to use `event` consistently (previously some payloads used `event_type`).
